**Array** boxes की एक ऐसी line है जो memory में एक-दूसरे से सटकर रखे होते हैं। हर box का एक
number होता है, जिसे उसका **index** कहते हैं, और गिनती `0` से शुरू होती है। अगर आपको index पता
है, तो आप सीधे किसी भी box तक पहुँच सकते हैं। इसीलिए values की list रखने का सबसे आसान और सबसे
तेज़ तरीका array है।

## असल ज़िंदगी में

Cinema hall की किसी एक row की seats के बारे में सोचिए। Seats ज़मीन में लगी होती हैं, एक के बाद
एक, और हर seat का एक number होता है। अगर आपके ticket पर seat 7 लिखा है, तो आप पहले seat 1 से 6
तक नहीं देखते। आप सीधे seat 7 पर जाते हैं।

Train का sleeper coach भी ऐसे ही काम करता है। आपका berth number आपको ठीक-ठीक बताता है कि कहाँ
जाना है, और coach में berths की गिनती तय होती है: coach बन जाने के बाद कोई उसमें एक और berth नहीं
जोड़ सकता।

इन उदाहरणों की दो बातें arrays के लिए ज़रूरी हैं:

- **Number वाली जगहें।** हर value की एक जगह होती है जहाँ आप सीधे पहुँच सकते हैं।
- **तय लंबाई।** Row में जगहों की गिनती तय होती है। ज़्यादा जगह चाहिए, तो एक नई और बड़ी row
  चाहिए।

एक फ़र्क है: cinema की seats आम तौर पर 1 से शुरू होती हैं, लेकिन code में पहला box index `0`
होता है।

## ये काम कैसे करता है

जब कोई program array बनाता है, तो computer memory का एक ऐसा हिस्सा अलग रख देता है जिसमें सारे
boxes एक-दूसरे के ठीक बगल में होते हैं, और हर box का size बराबर होता है। इसलिए वो एक छोटे से
हिसाब से पता कर लेता है कि कोई भी box कहाँ है:

```text
address of box i = address of box 0 + i * size of one box
```

अगर box `0` address `1000` से शुरू होता है और हर box 4 bytes लेता है, तो box `3` address
`1000 + 3 * 4 = 1012` पर है। न ढूँढना, न गिनना: इसीलिए किसी भी box को पढ़ना तुरंत हो जाता है।

हम एक ऐसा array बनाएँगे जिसमें boxes की गिनती तय है, यानी उसकी **capacity**, और एक दूसरा number
रखेंगे, **size**, जो गिनता है कि कितने boxes इस्तेमाल में हैं। Values हमेशा box `0` से
`size - 1` तक रहती हैं, बीच में कोई खाली जगह नहीं।

> **इसे खुद क्यों बनाएँ?** Python की `list`, C++ का `std::vector`, Java की `ArrayList` और
> JavaScript का array, सब अंदर से arrays ही हैं जो आपके लिए खुद बढ़ जाते हैं। (PHP का array असल में
> एक ordered map है; PHP में boxes की तय row के सबसे करीब `SplFixedArray` है।) एक fixed array
> खुद बनाने से आप वो खिसकाना देख पाते हैं जो ये पर्दे के पीछे करते हैं, और समझ पाते हैं कि कुछ
> operations तेज़ क्यों हैं और कुछ धीमे क्यों।

## Operations

### get: किसी index की value पढ़ना

1. अगर index `0` से कम है, या `size` से छोटा नहीं है, तो वहाँ कोई value नहीं है, इसलिए हम
   **index out of range** error देकर रुक जाते हैं।
2. नहीं तो, उस box की value लौटा दीजिए। कोई loop नहीं चाहिए।

### insert: किसी index पर value रखना

Values को सटकर ही रहना है, इसलिए `index` पर जगह बनाने के लिए `index` और उसके आगे की हर value
एक box दाईं ओर खिसकती है।

1. अगर `size` और `capacity` बराबर हैं, तो हर box भरा है, इसलिए हम **array is full** देकर रुक
   जाते हैं।
2. Index `0` से `size` तक कुछ भी हो सकता है। `size` पर insert करने का मतलब है आख़िर में जोड़ना,
   और तब कुछ भी नहीं खिसकाना पड़ता।
3. **आख़िर** से शुरू करके, हर value को एक box दाईं ओर खिसकाइए, जब तक `index` तक न पहुँच जाएँ।
4. नई value को `index` पर रखिए, और `size` में एक जोड़ दीजिए।

<!-- code: insert -->

आख़िर से ही क्यों शुरू करें? अगर आप पहले `index` वाली value खिसकाएँगे, तो वो अपने पड़ोसी के
खिसकने से पहले ही उस पर लिख देगी। दाएँ से बाएँ चलने पर, जिस box में आप लिखते हैं उसकी value पहले
ही copy हो चुकी होती है।

### remove: किसी index की value निकालना

1. Index जाँचिए, बिल्कुल `get` की तरह।
2. `index` वाली value याद रखिए।
3. खाली जगह भरिए: उसके बाद की हर value को एक box बाईं ओर खिसकाइए।
4. `size` में से एक घटाइए, और याद रखी हुई value लौटा दीजिए।

<!-- code: remove -->

आख़िरी box में अब भी किसी value की पुरानी copy रहती है, लेकिन वो `size` के बाहर है, इसलिए array
का हिस्सा नहीं है। ऊपर वाले playground में ये पुरानी copies हल्के रंग में दिखती हैं।

### search: कोई value कहाँ है, ये ढूँढना

Array को पता है कि हर box में क्या है, लेकिन ये नहीं कि कोई ख़ास value कहाँ है। इसलिए `search`
index `0` से शुरू करके boxes को एक-एक करके देखता है, और पहला मेल खाने वाला index लौटाता है, या
value न मिले तो `-1`। इसे **linear search** कहते हैं।

## ये कितना तेज़ है?

| Operation | ये क्या करता है | Time |
|---|---|---|
| `get` | किसी index का box पढ़ना | `O(1)` |
| आख़िर में `insert` | box `size` में लिखना, कुछ नहीं खिसकता | `O(1)` |
| किसी index पर `insert` | ज़्यादा से ज़्यादा `size` values दाईं ओर खिसकाना | `O(n)` |
| आख़िर से `remove` | कुछ नहीं खिसकता | `O(1)` |
| किसी index से `remove` | ज़्यादा से ज़्यादा `size` values बाईं ओर खिसकाना | `O(n)` |
| `search` | boxes को एक-एक करके देखना | `O(n)` |

यहाँ `n` values की गिनती है। Index `0` पर insert करना सबसे धीमा है, क्योंकि हर एक value को
खिसकना पड़ता है। `n` values की जगह वाले array को `O(n)` memory चाहिए, भले ही उसके ज़्यादातर
boxes खाली हों।

## आम गलतियाँ

- **1 से गिनना।** पहला box index `0` है और आख़िरी `size - 1`। Index `size` एक कदम आगे है।
- **Size और capacity में उलझना।** `capacity` बताती है कि कितने boxes हैं; `size` बताता है कि
  उनमें से कितनों में असली values हैं।
- **गलत दिशा में खिसकाना।** `insert` में आख़िर से index की ओर copy कीजिए। `remove` में index से
  आख़िर की ओर। उल्टा करने पर values खिसकने से पहले ही मिट जाती हैं।
- **Size बदलना भूल जाना।** हर insert एक जोड़ता है, और हर remove एक घटाता है।
- **बार-बार सबसे आगे insert करना।** हर insert सब कुछ खिसकाता है, इसलिए इस तरह `n` values जोड़ने
  में `O(n²)` time लगता है। जब भी हो सके, आख़िर में जोड़िए।

## ये कहाँ काम आता है?

- **लगभग हर जगह।** Lists, vectors, ArrayLists और JavaScript arrays, सब arrays पर ही बने हैं।
- **Images।** एक photo pixel colours का एक बड़ा array है।
- **Class register के marks।** हर roll number का एक mark: roll number ही index है।
- **Lookup tables**, जैसे हर महीने के दिनों की गिनती, जहाँ index से जवाब तुरंत मिल जाता है।
- **दूसरे structures।** इस course के stack और queue भी arrays पर ही बने हैं।
