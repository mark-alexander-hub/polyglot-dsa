**Queue** इति एका list अस्ति, यस्यां values एकस्मिन् अन्ते योज्यन्ते, यः **rear** इति कथ्यते,
अन्यस्मात् अन्तात् च निर्गच्छन्ति, यः **front** इति कथ्यते। यत् value प्रथमं योजितं, तत् एव प्रथमं
निर्गच्छति। एतत् **FIFO** इति कथ्यते: *First In, First Out*, अर्थात् यत् प्रथमम् आगतं तत् प्रथमं
गच्छति।

## वास्तविकजीवने

Railway ticket counter इत्यत्र पङ्क्तिं चिन्तयत। नवः यात्री पङ्क्तेः अन्ते तिष्ठति, कर्मचारी च यः अग्रे
अस्ति तस्य सेवां करोति। मध्यात् कस्यापि सेवा न भवति, यः च पश्चात् आगतः सः पूर्वम् आगतात् पूर्वं सेवां
न प्राप्नोति।

Computers अपि सर्वदा पङ्क्तौ प्रतीक्षन्ते:

- **Print jobs** queue इत्यस्यां प्रतीक्षन्ते। यदि त्रयः जनाः Print नुदन्ति, तर्हि पृष्ठानि तेन एव
  क्रमेण बहिः आगच्छन्ति येन ते नुदितवन्तः।
- यूयं यानि **messages** phone offline सति प्रेषयथ, तानि queue इत्यस्यां प्रतीक्षन्ते, network पुनः
  आगते च क्रमेण गच्छन्ति।
- **Video** अग्रिमाणि कतिपयानि seconds queue इत्यस्यां प्रतीक्षमाणानि रक्षति, येन तत् सम्यक् चलति।

## एतत् कथं कार्यं करोति

वयं queue इत्येतत् एकस्य array इत्यस्य उपरि रचयिष्यामः, यस्मिन् boxes इत्येतेषां संख्या निश्चिता
अस्ति। एषा संख्या **capacity** इति कथ्यते।

प्रायः जनानां प्रथमः विचारः एषः: values array इत्यस्य अन्ते योजयत, box 0 इत्यस्मात् च अपनयत। किन्तु
box 0 इत्यस्मात् अपनयने अन्यत् प्रत्येकं value एकं box वामं सारणीयं भवति, एतत् च मन्दम्। द्वितीयः
विचारः: एकं `front` index रक्षत, यदा च value निर्गच्छति तदा तत् केवलम् अग्रे सारयत। एतत् शीघ्रम्,
किन्तु इदानीं `front` इत्यतः पूर्वे boxes व्यर्थाः भवन्ति: कतिपयेषु dequeues इत्येतेषु परं queue
"पूर्णा" इति वदति, यद्यपि array इत्यस्य अर्धं रिक्तम् अस्ति।

समाधानम्: array इत्येतत् **वृत्तम्** इव गणयत। यदा वयम् अन्तिमं box अतिक्रामामः, तदा पुनः box 0 प्रति
गच्छामः। `%` (शेषः) operator एतत् परिभ्रमणम् अस्मदर्थं करोति: 5 boxes इत्येतेषु `(4 + 1) % 5`
इत्यस्य मूल्यं `0` भवति।

वयं द्वे संख्ये रक्षामः:

- `front` तस्य box इत्यस्य index अस्ति यस्मिन् प्राचीनतमं value अस्ति, यत् अग्रिमं निर्गमिष्यति।
- `count` इति इदानीं queue इत्यस्यां कति values सन्ति इति।

Rear इत्यस्य रक्षणम् अस्माकम् आवश्यकं नास्ति। अग्रिमः रिक्तः box `(front + count) % capacity` अस्ति,
नवीनतमं value च तस्मात् साक्षात् पूर्वं तिष्ठति।

> **`count` किमर्थं रक्षामः?** बहूनि पुस्तकानि `count` इत्यस्य स्थाने `rear` index रक्षन्ति। यदि `rear`
> इत्यस्य अर्थः "अग्रिमः रिक्तः box" इति, तर्हि `front == rear` इति queue रिक्तायां सत्यां पूर्णायां
> सत्यां च उभयत्र सत्यं भवति, अतः अतिरिक्तं नियमं विना द्वयोः भेदं ज्ञातुं न शक्यते। `count` इत्यनेन
> द्वे अपि परीक्षे स्पष्टे: रिक्ता इति `count == 0`, पूर्णा इति `count == capacity`।

## Operations

Queue इत्यस्याः त्रीणि मुख्यानि operations सन्ति। Values केवलं rear इत्यत्र योज्यन्ते, केवलं च front
इत्यस्मात् निर्गच्छन्ति।

### enqueue: rear इत्यत्र योजनम्

1. यदि `count` `capacity` इत्यस्य समानम् अस्ति, तर्हि प्रत्येकः box उपयोगे अस्ति। Queue पूर्णा अस्ति,
   अतः वयम् error इति दत्त्वा विरमामः।
2. अग्रिमं रिक्तं box गणयत: `(front + count) % capacity`। यदि तत् अन्तिमं box अतिक्रामति, तर्हि `%`
   तत् परिभ्राम्य array इत्यस्य आरम्भं प्रति नयति।
3. Value इत्येतत् तस्मिन् box इत्यस्मिन् स्थापयत, `count` इत्यस्मिन् च एकं योजयत।

### dequeue: front इत्यस्मात् निर्गमनम्

1. यदि `count` `0` अस्ति, तर्हि queue रिक्ता अस्ति। ग्रहीतुं किमपि नास्ति, अतः वयम् error इति दत्त्वा
   विरमामः।
2. `front` इत्यत्र स्थिते box इत्यस्मिन् यत् value अस्ति तत् स्मरत।
3. `front` इत्येतत् एकं स्थानम् अग्रे सारयत, `% capacity` इत्यनेन परिभ्रामयत, `count` इत्यस्मात् एकं
   न्यूनीकुरुत, स्मृतं value च प्रत्यर्पयत (return)।

<!-- code: dequeue -->

Stack इत्यस्मिन् इव अत्रापि वयं पुरातनं value **न मार्जयामः**। सः box इदानीं queue इत्यस्याः बहिः
अस्ति, पश्चात् आगच्छन् `enqueue` च तस्य उपरि लिखिष्यति। उपरि स्थिते playground इत्यस्मिन् एतानि
पुरातनानि values मन्दवर्णेन दृश्यन्ते।

### peek: front इत्येतत् अनपनीय दर्शनम्

`peek` `front` इत्यत्र स्थितं value प्रत्यर्पयति, किमपि च न परिवर्तयति। Ticket counter इत्यस्य
कर्मचारी अग्रिमम् आह्वानात् पूर्वं कः अग्रिमः इति एवम् एव पश्यति।

## एतत् कियत् शीघ्रम्?

प्रत्येकम् operation किञ्चित् गणनां करोति, एकं च box स्पृशति, queue कियती अपि दीर्घा अस्तु। अतः
सर्वाणि समानम् अल्पं च समयं गृह्णन्ति, `O(1)`। अत एव वयं वृत्तम् उपयुञ्ज्महे: "box 0 इत्यस्मात् अपनीय
सर्वान् सारयत" इति रूपस्य प्रत्येकं dequeue `O(n)` अपेक्षते।

| Operation | एतत् किं करोति | Time |
|---|---|---|
| `enqueue` | rear इत्यत्र value इत्यस्य योजनम् | `O(1)` |
| `dequeue` | front इत्यत्र स्थितस्य value इत्यस्य अपनयनम् | `O(1)` |
| `peek` | front इत्यत्र स्थितस्य value इत्यस्य दर्शनम् | `O(1)` |
| `isEmpty` | `count` `0` अस्ति न वा इति परीक्षणम् | `O(1)` |
| कस्यचित् value इत्यस्य अन्वेषणम् | values इत्येतेषाम् एकैकशः दर्शनम् | `O(n)` |

`n` values इत्येतेषां स्थानयुक्ता queue `n` boxes उपयुङ्क्ते, अतः तस्याः `O(n)` memory आवश्यकम्।

## सामान्याः त्रुटयः

- **परिभ्रमणस्य विस्मरणम्।** `(front + 1) % capacity` इत्यस्य स्थाने `front + 1` इति लेखनं कतिपयेषु
  operations इत्येतेषु परं array इत्यस्य अन्तम् अतिक्रामति।
- **पूर्णा-रिक्तयोः भ्रमः।** यदि यूयं केवलं `front`, `rear` च रक्षथ, तर्हि उभे अपि समाने दृश्येते।
  `count` रक्षत, अथवा सदा एकं box रिक्तं त्यजत।
- **अनुचितात् अन्तात् अपनयनम्।** Values front इत्यस्मात् निर्गच्छन्ति। यदि युष्माकं `dequeue`
  *नवीनतमं* value प्रत्यर्पयति, तर्हि यूयं प्रमादेन stack रचितवन्तः।
- **Dequeue इत्यस्मिन् प्रत्येकस्य value इत्यस्य सारणम्।** एतत् कार्यं करोति, किन्तु `O(1)` operation
  इत्येतत् `O(n)` इति करोति। JavaScript इत्यस्मिन् `array.shift()` एतदेव करोति, PHP इत्यस्मिन्
  `array_shift()` अपि।

## एतत् कुत्र प्रयुज्यते?

- **Printer queues**, यथा उपरि दृष्टम्।
- **CPU scheduling।** Operating system तानि programs queues इत्येतासु रक्षति यानि processor इत्यस्मिन्
  स्वं क्रमं प्रतीक्षन्ते।
- **Breadth-first search** एकं graph अथवा maze स्तरशः अन्विष्यति, यानि च स्थानानि अद्यापि द्रष्टव्यानि
  तानि queue इत्यस्यां रक्षति।
- Apps, servers इत्येतेषां मध्ये **messages** queues इत्येतासु प्रतीक्षन्ते, येन एकस्मिन् पक्षे व्यस्ते
  सति अपि किमपि न नश्यति।
- **Video, music buffering**: stream इत्यस्य अग्रिमाणि खण्डानि queue इत्यस्यां प्रतीक्षन्ते।

## एतानि कृत्वा पश्यत

1. Playground इत्यस्मिन् reset नुदत, ततः `5, 6, 7` enqueue कुरुत, एकवारं dequeue कुरुत, `8` च
   enqueue कुरुत। `8` कस्मिन् box इत्यस्मिन् गच्छति, front इत्यत्र च किं value अस्ति?
2. Capacity 5 युक्तायां queue इत्यस्यां `front` `3` अस्ति, `count` च `2`। अग्रिमं value कस्मिन् box
   इत्यस्मिन् गच्छति? `%` इत्यनेन गणयत, ततः program इत्यस्मिन् परीक्षणं कुरुत।
3. Queue इत्यस्याः साहाय्येन ticket counter चालयत: पञ्च नामानि enqueue कुरुत, ततः तानि एकैकशः
   सेवयत (dequeue), प्रत्येकं नाम च मुद्रयत (print)।
4. Program इत्येतत् तथा परिवर्तयत यथा पूर्णायां queue इत्यस्यां `enqueue` करणे error इत्यस्य स्थाने
   capacity द्विगुणा भवेत्। सावधानाः भवत: values नवीने array इत्यस्मिन् queue इत्यस्याः क्रमेण, `front`
   इत्यतः आरभ्य, प्रतिलिखत।
