**Queue** एक ऐसी list है जिसमें values एक सिरे से जुड़ती हैं, जिसे **rear** कहते हैं, और दूसरे
सिरे से निकलती हैं, जिसे **front** कहते हैं। जो value सबसे पहले जुड़ी, वही सबसे पहले निकलती है।
इसे **FIFO** कहते हैं: *First In, First Out*, यानी जो पहले आया, वो पहले जाएगा।

## असल ज़िंदगी में

रेलवे की टिकट खिड़की पर लगी लाइन के बारे में सोचिए। नया यात्री लाइन में सबसे पीछे जुड़ता है, और
clerk उसे टिकट देता है जो सबसे आगे खड़ा है। किसी को बीच से टिकट नहीं मिलता, और जो बाद में आया
उसे पहले आए इंसान से पहले टिकट नहीं मिलता।

Computer में भी चीज़ें हर समय लाइन में इंतज़ार करती हैं:

- **Print jobs** एक queue में इंतज़ार करते हैं। अगर तीन लोग Print दबाएँ, तो pages उसी क्रम में
  निकलते हैं जिस क्रम में उन्होंने दबाया था।
- Phone offline होने पर आप जो **messages** भेजते हैं, वे एक queue में रुकते हैं और network वापस
  आने पर क्रम से चले जाते हैं।
- **Video** अगले कुछ seconds को एक queue में तैयार रखता है, ताकि वो बिना रुके चले।

## ये काम कैसे करता है

हम queue को एक array पर बनाएँगे जिसमें boxes की गिनती तय है। इस गिनती को **capacity** कहते हैं।

ज़्यादातर लोगों का पहला idea होता है: values को array के आख़िर में जोड़ो और box 0 से निकालो। लेकिन
box 0 से निकालने का मतलब है कि बाकी हर value को एक box बाईं ओर खिसकाना पड़ेगा, जो धीमा है। दूसरा
idea है एक `front` index रखना और value निकलने पर उसे बस आगे बढ़ा देना। ये तेज़ है, लेकिन अब
`front` से पहले वाले boxes बेकार हो जाते हैं: कुछ dequeues के बाद queue कहती है "भरी हुई है", जबकि
आधा array खाली पड़ा है।

इसका हल है array को एक **गोल घेरे** (circle) की तरह मानना। जब हम आख़िरी box से आगे बढ़ते हैं, तो
वापस box 0 पर पहुँच जाते हैं। ये घुमाने का काम `%` (remainder) operator हमारे लिए करता है: 5 boxes
के साथ `(4 + 1) % 5` का जवाब `0` है।

हम दो numbers रखते हैं:

- `front` उस box का index है जिसमें सबसे पुरानी value है, यानी अगली निकलने वाली value।
- `count` बताता है कि अभी queue में कितनी values हैं।

Rear को अलग से रखने की ज़रूरत नहीं है। अगला खाली box `(front + count) % capacity` है, और सबसे नई
value उससे ठीक पहले वाले box में है।

> **`count` क्यों रखें?** कई किताबें `count` की जगह एक `rear` index रखती हैं। अगर `rear` का मतलब
> "अगला खाली box" है, तो `front == rear` तब भी सच होता है जब queue खाली है और तब भी जब queue भरी
> हुई है, इसलिए किसी extra नियम के बिना आप दोनों में फ़र्क नहीं कर सकते। `count` के साथ दोनों जाँच
> आसान हैं: खाली मतलब `count == 0`, भरी हुई मतलब `count == capacity`।

## Operations

Queue के तीन मुख्य operations हैं। Values सिर्फ़ rear पर जुड़ती हैं और सिर्फ़ front से निकलती हैं।

### enqueue: rear पर जुड़ना

1. अगर `count` और `capacity` बराबर हैं, तो हर box इस्तेमाल में है। Queue भरी हुई है, इसलिए हम error
   देकर रुक जाते हैं।
2. अगला खाली box निकालिए: `(front + count) % capacity`। अगर ये आख़िरी box से आगे चला जाए, तो `%`
   उसे घुमाकर array की शुरुआत पर ले आता है।
3. Value उस box में रखिए और `count` में एक जोड़िए।

### dequeue: front से निकलना

1. अगर `count` की value `0` है, तो queue खाली है। निकालने के लिए कुछ नहीं है, इसलिए हम error देकर
   रुक जाते हैं।
2. `front` वाले box की value याद रखिए।
3. `front` को एक आगे खिसकाइए (`% capacity` से घुमाते हुए), `count` में से एक घटाइए, और याद रखी हुई
   value लौटा दीजिए।

Stack की तरह, यहाँ भी हम पुरानी value को **मिटाते नहीं** हैं। वो box अब queue के बाहर है, और आगे कोई
`enqueue` उस पर नई value लिख देगा। ऊपर वाले playground में ये पुरानी values हल्के रंग में दिखती हैं।

### peek: front को बिना हटाए देखना

`peek` बस `front` वाली value लौटाता है और कुछ नहीं बदलता। टिकट clerk भी किसी को बुलाने से पहले ऐसे
ही देखता है कि अगला कौन है।

## ये कितना तेज़ है?

Queue चाहे जितनी लंबी हो, हर operation थोड़ा-सा हिसाब करता है और सिर्फ़ एक box को छूता है। इसलिए सबमें
बराबर और बहुत कम समय लगता है, `O(1)`। Circle वाला तरीका हम इसी वजह से इस्तेमाल करते हैं: "box 0 से
निकालो और सबको खिसकाओ" वाले तरीके में हर dequeue को `O(n)` समय लगता है।

| Operation | ये क्या करता है | Time |
|---|---|---|
| `enqueue` | rear पर value जोड़ना | `O(1)` |
| `dequeue` | front वाली value निकालना | `O(1)` |
| `peek` | front वाली value देखना | `O(1)` |
| `isEmpty` | देखना कि `count` की value `0` है या नहीं | `O(1)` |
| कोई value ढूँढना | values को एक-एक करके देखना | `O(n)` |

`n` values की जगह वाली queue `n` boxes इस्तेमाल करती है, इसलिए उसे `O(n)` memory चाहिए।

## आम गलतियाँ

- **घुमाना भूल जाना।** `(front + 1) % capacity` की जगह `front + 1` लिखने से कुछ operations के बाद आप
  array के आख़िर से बाहर निकल जाते हैं।
- **भरी और खाली queue में गड़बड़।** अगर आप सिर्फ़ `front` और `rear` रखते हैं, तो दोनों हालत एक जैसी
  दिख सकती हैं। `count` रखिए, या एक box हमेशा खाली छोड़िए।
- **गलत सिरे से निकालना।** Values front से निकलती हैं। अगर आपका `dequeue` *सबसे नई* value लौटाता
  है, तो आपने गलती से stack बना दिया है।
- **हर dequeue पर सारी values खिसकाना।** ये चलता तो है, लेकिन `O(1)` वाले operation को `O(n)` बना
  देता है। JavaScript में `array.shift()` और PHP में `array_shift()` ठीक यही करते हैं।

## ये कहाँ काम आता है?

- **Printer queues**, जैसा ऊपर देखा।
- **CPU scheduling।** Operating system उन programs को queues में रखता है जो processor पर अपनी बारी
  का इंतज़ार कर रहे हैं।
- **Breadth-first search** किसी graph या maze को एक-एक level करके खोजता है, और जिन जगहों पर अभी
  जाना बाकी है उन्हें एक queue में रखता है।
- Apps और servers के बीच **messages** queues में इंतज़ार करते हैं, ताकि एक तरफ़ busy होने पर भी कुछ
  खोए नहीं।
- **Video और music buffering**: stream के अगले हिस्से एक queue में इंतज़ार करते हैं।

3. Queue से एक टिकट खिड़की चलाइए: पाँच नाम enqueue कीजिए, फिर उन्हें एक-एक करके serve (dequeue)
   कीजिए और हर नाम print कीजिए।
4. Program को ऐसे बदलिए कि भरी हुई queue पर `enqueue` करने से error की जगह capacity दोगुनी हो जाए।
   ध्यान रखिए: values को नए array में queue के क्रम में copy कीजिए, `front` से शुरू करके।
