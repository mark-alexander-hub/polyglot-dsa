**Queue** என்பது values ஒரு முனையில் சேர்ந்து, மறுமுனையில் வெளியேறும் ஒரு list. Values சேரும் முனைக்கு
**rear** என்றும், வெளியேறும் முனைக்கு **front** என்றும் பெயர். முதலில் சேர்ந்த value தான் முதலில்
வெளியேறும். இதை **FIFO** என்பார்கள்: *First In, First Out*, அதாவது முதலில் வந்தது முதலில் போகும்.

## அன்றாட வாழ்க்கையில்

ரயில்வே டிக்கெட் கவுண்டரில் வரிசையில் நிற்பவர்களை நினைத்துப் பாருங்கள். புதிதாக வரும் பயணி வரிசையின்
கடைசியில் சேர்கிறார், clerk வரிசையின் முன்னால் நிற்பவருக்கு டிக்கெட் கொடுக்கிறார். நடுவில் நிற்கும்
யாருக்கும் முதலில் டிக்கெட் கிடைக்காது, பின்னால் வந்தவருக்கு முன்பே வந்தவரை விட முன்னதாகக் கிடைக்காது.

Computer-இலும் பல விஷயங்கள் இப்படித்தான் காத்திருக்கின்றன:

- **Print jobs** ஒரு queue-இல் காத்திருக்கின்றன. மூன்று பேர் Print அழுத்தினால், அவர்கள் அழுத்திய வரிசை
  முறையிலேயே pages வெளியே வரும்.
- Phone offline-ஆக இருக்கும்போது நீங்கள் அனுப்பும் **messages** ஒரு queue-இல் காத்திருந்து, network
  திரும்ப வந்ததும் வரிசை முறைப்படி போகும்.
- **Video** அடுத்த சில seconds-ஐ ஒரு queue-இல் தயாராக வைத்துக்கொள்கிறது, அதனால் அது தடையில்லாமல் play
  ஆகிறது.

## இது எப்படி வேலை செய்கிறது

நிலையான எண்ணிக்கையில் boxes உள்ள ஒரு array மேல் queue-ஐ உருவாக்கப் போகிறோம். அந்த எண்ணிக்கைக்கு
**capacity** என்று பெயர்.

பெரும்பாலானோருக்கு முதலில் தோன்றும் idea: values-ஐ array-இன் கடைசியில் சேர்த்து, box 0-இலிருந்து
எடுப்பது. ஆனால் box 0-இலிருந்து எடுத்தால், மீதமுள்ள ஒவ்வொரு value-ஐயும் ஒரு box இடப்பக்கம் நகர்த்த
வேண்டும், அது மெதுவானது. இரண்டாவது idea: ஒரு `front` index வைத்துக்கொண்டு, value வெளியேறும்போது அதை
வெறுமனே முன்னால் நகர்த்துவது. இது வேகமானது, ஆனால் இப்போது `front`-க்கு முந்தைய boxes வீணாகின்றன: சில
dequeues-க்குப் பிறகு array பாதி காலியாக இருந்தாலும் queue "நிரம்பியது" என்று சொல்லும்.

இதற்குத் தீர்வு: array-ஐ ஒரு **வட்டம்** (circle) போலப் பார்ப்பது. கடைசி box-ஐத் தாண்டும்போது மீண்டும்
box 0-க்கு வருகிறோம். இப்படிச் சுற்றி வரும் வேலையை `%` (remainder) operator நமக்காகச் செய்கிறது: 5
boxes இருக்கும்போது `(4 + 1) % 5` என்பது `0`.

இரண்டு numbers-ஐ வைத்துக்கொள்கிறோம்:

- `front` என்பது மிகப் பழைய value உள்ள box-இன் index, அதாவது அடுத்து வெளியேறப் போகும் value.
- `count` இப்போது queue-இல் எத்தனை values உள்ளன என்று சொல்கிறது.

Rear-ஐத் தனியாக வைக்கத் தேவையில்லை. அடுத்த காலி box `(front + count) % capacity`, மிகப் புதிய value
அதற்கு முந்தைய box-இல் இருக்கும்.

> **`count` ஏன் வைக்க வேண்டும்?** பல புத்தகங்கள் `count`-க்குப் பதிலாக ஒரு `rear` index வைக்கின்றன.
> `rear` என்பதை "அடுத்த காலி box" என்று வைத்தால், queue காலியாக இருக்கும்போதும் நிரம்பியிருக்கும்போதும்
> `front == rear` உண்மையாகிவிடும், அதனால் கூடுதல் விதி இல்லாமல் இரண்டையும் பிரித்தறிய முடியாது. `count`
> இருந்தால் இரண்டு சரிபார்ப்புகளும் எளிது: காலி என்றால் `count == 0`, நிரம்பியது என்றால்
> `count == capacity`.

## Operations

Queue-க்கு மூன்று முக்கிய operations உள்ளன. Values rear-இல் மட்டுமே சேரும், front-இலிருந்து மட்டுமே
வெளியேறும்.

### enqueue: rear-இல் சேர்வது

1. `count`-உம் `capacity`-உம் சமமாக இருந்தால், எல்லா boxes-உம் பயன்பாட்டில் உள்ளன. Queue நிரம்பியது,
   அதனால் error கொடுத்து நிறுத்துகிறோம்.
2. அடுத்த காலி box-ஐக் கண்டுபிடியுங்கள்: `(front + count) % capacity`. அது கடைசி box-ஐத் தாண்டினால்,
   `%` அதைச் சுற்றி array-இன் தொடக்கத்துக்குக் கொண்டு வரும்.
3. Value-ஐ அந்த box-இல் வைத்து, `count`-உடன் ஒன்றைக் கூட்டுங்கள்.

<!-- code: enqueue -->

### dequeue: front-இலிருந்து வெளியேறுவது

1. `count`-இன் value `0` என்றால், queue காலியாக உள்ளது. எடுக்க எதுவும் இல்லை, அதனால் error கொடுத்து
   நிறுத்துகிறோம்.
2. `front`-இல் உள்ள box-இன் value-ஐ நினைவில் வைத்துக்கொள்ளுங்கள்.
3. `front`-ஐ ஒன்று முன்னால் நகர்த்துங்கள் (`% capacity` மூலம் சுற்றி), `count`-இலிருந்து ஒன்றைக்
   கழித்து, நினைவில் வைத்த value-ஐ return செய்யுங்கள்.

<!-- code: dequeue -->

Stack போலவே, இங்கும் பழைய value-ஐ நாம் **அழிப்பதில்லை**. அந்த box இப்போது queue-க்கு வெளியே உள்ளது,
பின்னால் வரும் ஒரு `enqueue` அதன் மேல் புதிய value-ஐ எழுதும். மேலே உள்ள playground-இல் இந்தப் பழைய
values மங்கலாகத் தெரியும்.

### peek: front-ஐ நீக்காமல் பார்ப்பது

`peek` வெறுமனே `front`-இல் உள்ள value-ஐ return செய்கிறது, எதையும் மாற்றுவதில்லை. டிக்கெட் clerk-உம்
அடுத்தவரை அழைப்பதற்கு முன் இப்படித்தான் யார் அடுத்து என்று பார்க்கிறார்.

## இது எவ்வளவு வேகமானது?

Queue எவ்வளவு நீளமாக இருந்தாலும், ஒவ்வொரு operation-உம் கொஞ்சம் கணக்குப் போட்டு ஒரே ஒரு box-ஐ மட்டுமே
தொடுகிறது. அதனால் எல்லாவற்றுக்கும் ஒரே அளவு குறைந்த நேரம் தான் ஆகும், `O(1)`. இதற்காகத் தான் circle
முறையைப் பயன்படுத்துகிறோம்: "box 0-இலிருந்து எடுத்து எல்லாவற்றையும் நகர்த்தும்" முறையில் ஒவ்வொரு
dequeue-க்கும் `O(n)` ஆகும்.

| Operation | இது என்ன செய்கிறது | Time |
|---|---|---|
| `enqueue` | rear-இல் value சேர்ப்பது | `O(1)` |
| `dequeue` | front-இல் உள்ள value-ஐ எடுப்பது | `O(1)` |
| `peek` | front value-ஐப் பார்ப்பது | `O(1)` |
| `isEmpty` | `count`-இன் value `0` தானா என்று பார்ப்பது | `O(1)` |
| ஒரு value-ஐத் தேடுவது | values-ஐ ஒவ்வொன்றாகப் பார்ப்பது | `O(n)` |

`n` values-க்கு இடம் உள்ள queue `n` boxes பயன்படுத்துகிறது, அதனால் அதற்கு `O(n)` memory தேவை.

## பொதுவான தவறுகள்

- **சுற்ற மறப்பது.** `(front + 1) % capacity`-க்குப் பதிலாக `front + 1` என்று எழுதினால், சில
  operations-க்குப் பிறகு array-இன் கடைசியைத் தாண்டிப் போய்விடுவீர்கள்.
- **நிரம்பிய queue-ஐயும் காலியான queue-ஐயும் குழப்புவது.** `front`, `rear` மட்டும் வைத்தால், இரண்டு
  நிலைகளும் ஒரே மாதிரி தெரியலாம். `count` வையுங்கள், அல்லது ஒரு box-ஐ எப்போதும் காலியாக விடுங்கள்.
- **தவறான முனையிலிருந்து எடுப்பது.** Values front-இலிருந்து வெளியேறும். உங்கள் `dequeue` *மிகப் புதிய*
  value-ஐ return செய்தால், நீங்கள் தெரியாமல் stack உருவாக்கிவிட்டீர்கள்.
- **ஒவ்வொரு dequeue-இலும் எல்லா values-ஐயும் நகர்த்துவது.** இது வேலை செய்யும், ஆனால் `O(1)`
  operation-ஐ `O(n)` ஆக்கிவிடும். JavaScript-இல் `array.shift()`-உம் PHP-இல் `array_shift()`-உம் சரியாக இதைத் தான் செய்கின்றன.

## இது எங்கே பயன்படுகிறது?

- **Printer queues**, மேலே பார்த்தது போல.
- **CPU scheduling.** Processor-இல் தங்கள் முறைக்காகக் காத்திருக்கும் programs-ஐ operating system
  queues-இல் வைக்கிறது.
- **Breadth-first search** ஒரு graph அல்லது maze-ஐ ஒவ்வொரு level-ஆகத் தேடுகிறது, இன்னும் போக வேண்டிய
  இடங்களை ஒரு queue-இல் வைக்கிறது.
- Apps, servers இடையே போகும் **messages** queues-இல் காத்திருக்கின்றன, அதனால் ஒரு பக்கம் busy-ஆக
  இருந்தாலும் எதுவும் தொலைவதில்லை.
- **Video, music buffering**: stream-இன் அடுத்த பகுதிகள் ஒரு queue-இல் காத்திருக்கின்றன.

## இவற்றைச் செய்து பாருங்கள்

1. Playground-இல் reset அழுத்தி, பிறகு `5, 6, 7` enqueue செய்து, ஒருமுறை dequeue செய்து, `8` enqueue
   செய்யுங்கள். `8` எந்த box-க்குப் போனது, front-இல் எந்த value உள்ளது?
2. Capacity 5 உள்ள ஒரு queue-இல் `front`-இன் value `3`, `count`-இன் value `2`. அடுத்த value எந்த
   box-க்குப் போகும்? `%` மூலம் கணக்கிட்டு, பிறகு program-இல் சரிபாருங்கள்.
3. Queue பயன்படுத்தி ஒரு டிக்கெட் கவுண்டரை நடத்துங்கள்: ஐந்து பெயர்களை enqueue செய்து, பிறகு அவர்களை
   ஒவ்வொருவராக serve (dequeue) செய்து, ஒவ்வொரு பெயரையும் print செய்யுங்கள்.
4. நிரம்பிய queue-இல் `enqueue` செய்யும்போது error-க்குப் பதிலாக capacity இரண்டு மடங்காகும்படி
   program-ஐ மாற்றுங்கள். கவனம்: values-ஐப் புதிய array-க்கு queue வரிசை முறைப்படி, `front`-இலிருந்து
   தொடங்கி copy செய்யுங்கள்.
