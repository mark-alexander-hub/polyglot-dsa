**Queue** ಎಂದರೆ values ಒಂದು ತುದಿಯಲ್ಲಿ ಸೇರುವ ಮತ್ತು ಇನ್ನೊಂದು ತುದಿಯಿಂದ ಹೊರಹೋಗುವ ಒಂದು list. Values
ಸೇರುವ ತುದಿಯನ್ನು **rear** ಎನ್ನುತ್ತಾರೆ, ಹೊರಹೋಗುವ ತುದಿಯನ್ನು **front** ಎನ್ನುತ್ತಾರೆ. ಮೊದಲು ಸೇರಿದ
value ಮೊದಲು ಹೊರಹೋಗುತ್ತದೆ. ಇದನ್ನು **FIFO** ಎನ್ನುತ್ತಾರೆ: *First In, First Out*, ಅಂದರೆ ಮೊದಲು ಬಂದದ್ದು
ಮೊದಲು ಹೋಗುತ್ತದೆ.

## ನಿಜ ಜೀವನದಲ್ಲಿ

ರೈಲ್ವೆ ಟಿಕೆಟ್ ಕೌಂಟರ್ ಮುಂದಿನ ಸಾಲಿನ ಬಗ್ಗೆ ಯೋಚಿಸಿ. ಹೊಸ ಪ್ರಯಾಣಿಕರು ಸಾಲಿನ ಕೊನೆಯಲ್ಲಿ ಸೇರುತ್ತಾರೆ, ಮತ್ತು
clerk ಸಾಲಿನ ಮುಂದೆ ಇರುವವರಿಗೆ ಟಿಕೆಟ್ ಕೊಡುತ್ತಾರೆ. ಮಧ್ಯದಲ್ಲಿರುವ ಯಾರಿಗೂ ಮೊದಲು ಟಿಕೆಟ್ ಸಿಗುವುದಿಲ್ಲ, ಮತ್ತು
ತಡವಾಗಿ ಬಂದವರಿಗೆ ಬೇಗ ಬಂದವರಿಗಿಂತ ಮೊದಲು ಸಿಗುವುದಿಲ್ಲ.

Computer ನಲ್ಲೂ ವಿಷಯಗಳು ಸದಾ ಸಾಲಿನಲ್ಲಿ ಕಾಯುತ್ತವೆ:

- **Print jobs** ಒಂದು queue ನಲ್ಲಿ ಕಾಯುತ್ತವೆ. ಮೂವರು Print ಒತ್ತಿದರೆ, ಅವರು ಒತ್ತಿದ ಕ್ರಮದಲ್ಲೇ pages
  ಹೊರಬರುತ್ತವೆ.
- Phone offline ಇದ್ದಾಗ ನೀವು ಕಳುಹಿಸುವ **messages** ಒಂದು queue ನಲ್ಲಿ ಕಾಯುತ್ತವೆ, network ಮರಳಿ ಬಂದಾಗ
  ಕ್ರಮವಾಗಿ ಹೋಗುತ್ತವೆ.
- **Video** ಮುಂದಿನ ಕೆಲವು seconds ಅನ್ನು ಒಂದು queue ನಲ್ಲಿ ಸಿದ್ಧವಾಗಿ ಇಟ್ಟುಕೊಳ್ಳುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದು
  ನಿಲ್ಲದೆ play ಆಗುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ನಾವು queue ಅನ್ನು ನಿಗದಿತ ಸಂಖ್ಯೆಯ boxes ಇರುವ ಒಂದು array ಮೇಲೆ ಕಟ್ಟುತ್ತೇವೆ. ಆ ಸಂಖ್ಯೆಯನ್ನು **capacity**
ಎನ್ನುತ್ತಾರೆ.

ಹೆಚ್ಚಿನವರಿಗೆ ಮೊದಲು ಬರುವ idea: values ಅನ್ನು array ಯ ಕೊನೆಯಲ್ಲಿ ಸೇರಿಸುವುದು, box 0 ನಿಂದ ತೆಗೆಯುವುದು.
ಆದರೆ box 0 ನಿಂದ ತೆಗೆದರೆ ಉಳಿದ ಪ್ರತಿ value ಅನ್ನೂ ಒಂದು box ಎಡಕ್ಕೆ ಸರಿಸಬೇಕಾಗುತ್ತದೆ, ಅದು ನಿಧಾನ. ಎರಡನೇ
idea: ಒಂದು `front` index ಇಟ್ಟುಕೊಂಡು, value ಹೊರಹೋದಾಗ ಅದನ್ನು ಸುಮ್ಮನೆ ಮುಂದೆ ಸರಿಸುವುದು. ಇದು ವೇಗ, ಆದರೆ
ಈಗ `front` ಗಿಂತ ಹಿಂದಿನ boxes ವ್ಯರ್ಥವಾಗುತ್ತವೆ: ಕೆಲವು dequeues ನಂತರ array ಅರ್ಧ ಖಾಲಿ ಇದ್ದರೂ queue
"ತುಂಬಿದೆ" ಎನ್ನುತ್ತದೆ.

ಇದಕ್ಕೆ ಪರಿಹಾರ: array ಅನ್ನು ಒಂದು **ವೃತ್ತ** (circle) ಎಂದು ನೋಡುವುದು. ಕೊನೆಯ box ದಾಟಿದಾಗ ನಾವು ಮತ್ತೆ
box 0 ಗೆ ಬರುತ್ತೇವೆ. ಈ ಸುತ್ತಿಸುವ ಕೆಲಸವನ್ನು `%` (remainder) operator ನಮಗಾಗಿ ಮಾಡುತ್ತದೆ: 5 boxes
ಇದ್ದಾಗ `(4 + 1) % 5` ಎಂದರೆ `0`.

ನಾವು ಎರಡು numbers ಇಟ್ಟುಕೊಳ್ಳುತ್ತೇವೆ:

- `front` ಅತ್ಯಂತ ಹಳೆಯ value ಇರುವ box ನ index, ಅಂದರೆ ಮುಂದೆ ಹೊರಹೋಗುವ value.
- `count` ಈಗ queue ನಲ್ಲಿ ಎಷ್ಟು values ಇವೆ ಎಂದು ಹೇಳುತ್ತದೆ.

Rear ಅನ್ನು ಬೇರೆಯಾಗಿ ಇಡಬೇಕಾಗಿಲ್ಲ. ಮುಂದಿನ ಖಾಲಿ box `(front + count) % capacity`, ಮತ್ತು ಅತ್ಯಂತ ಹೊಸ
value ಅದರ ಹಿಂದಿನ box ನಲ್ಲಿರುತ್ತದೆ.

<!-- code: setup -->

> **`count` ಏಕೆ ಇಡಬೇಕು?** ಹಲವು ಪುಸ್ತಕಗಳು `count` ಬದಲು ಒಂದು `rear` index ಇಡುತ್ತವೆ. `rear` ಎಂದರೆ
> "ಮುಂದಿನ ಖಾಲಿ box" ಆದರೆ, queue ಖಾಲಿ ಇದ್ದಾಗಲೂ ತುಂಬಿದ್ದಾಗಲೂ `front == rear` ನಿಜವಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ
> ಹೆಚ್ಚುವರಿ ನಿಯಮ ಇಲ್ಲದೆ ಎರಡನ್ನೂ ಬೇರ್ಪಡಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. `count` ಇದ್ದರೆ ಎರಡೂ ಪರಿಶೀಲನೆಗಳು ಸುಲಭ: ಖಾಲಿ
> ಎಂದರೆ `count == 0`, ತುಂಬಿದೆ ಎಂದರೆ `count == capacity`.

## Operations

Queue ಗೆ ಮೂರು ಮುಖ್ಯ operations ಇವೆ. Values rear ನಲ್ಲಿ ಮಾತ್ರ ಸೇರುತ್ತವೆ, front ನಿಂದ ಮಾತ್ರ
ಹೊರಹೋಗುತ್ತವೆ.

### enqueue: rear ನಲ್ಲಿ ಸೇರುವುದು

1. `count` ಮತ್ತು `capacity` ಸಮವಾಗಿದ್ದರೆ ಎಲ್ಲಾ boxes ಬಳಕೆಯಲ್ಲಿವೆ. Queue ತುಂಬಿದೆ, ಆದ್ದರಿಂದ ನಾವು
   error ಕೊಟ್ಟು ನಿಲ್ಲಿಸುತ್ತೇವೆ.
2. ಮುಂದಿನ ಖಾಲಿ box ಕಂಡುಹಿಡಿಯಿರಿ: `(front + count) % capacity`. ಅದು ಕೊನೆಯ box ದಾಟಿದರೆ, `%` ಅದನ್ನು
   ಸುತ್ತಿಸಿ array ಯ ಆರಂಭಕ್ಕೆ ತರುತ್ತದೆ.
3. Value ಅನ್ನು ಆ box ನಲ್ಲಿ ಇಡಿ, `count` ಗೆ ಒಂದು ಸೇರಿಸಿ.

<!-- code: enqueue -->

### dequeue: front ನಿಂದ ಹೊರಹೋಗುವುದು

1. `count` ನ value `0` ಆಗಿದ್ದರೆ queue ಖಾಲಿ ಇದೆ. ತೆಗೆಯಲು ಏನೂ ಇಲ್ಲ, ಆದ್ದರಿಂದ ನಾವು error ಕೊಟ್ಟು
   ನಿಲ್ಲಿಸುತ್ತೇವೆ.
2. `front` ನಲ್ಲಿರುವ box ನ value ಅನ್ನು ನೆನಪಿಟ್ಟುಕೊಳ್ಳಿ.
3. `front` ಅನ್ನು ಒಂದು ಮುಂದೆ ಸರಿಸಿ (`% capacity` ಬಳಸಿ ಸುತ್ತಿಸುತ್ತಾ), `count` ನಿಂದ ಒಂದು ಕಳೆಯಿರಿ,
   ನೆನಪಿಟ್ಟ value ಅನ್ನು return ಮಾಡಿ.

<!-- code: dequeue -->

Stack ನಂತೆಯೇ, ಇಲ್ಲೂ ನಾವು ಹಳೆಯ value ಅನ್ನು **ಅಳಿಸುವುದಿಲ್ಲ**. ಆ box ಈಗ queue ನ ಹೊರಗಿದೆ, ಮುಂದೆ
ಯಾವುದಾದರೂ `enqueue` ಅದರ ಮೇಲೆ ಹೊಸ value ಬರೆಯುತ್ತದೆ. ಮೇಲಿನ playground ನಲ್ಲಿ ಈ ಹಳೆಯ values ಮಸುಕಾಗಿ
ಕಾಣುತ್ತವೆ.

### peek: front ಅನ್ನು ತೆಗೆಯದೆ ನೋಡುವುದು

`peek` ಕೇವಲ `front` ನಲ್ಲಿರುವ value ಅನ್ನು return ಮಾಡುತ್ತದೆ, ಏನನ್ನೂ ಬದಲಿಸುವುದಿಲ್ಲ. ಟಿಕೆಟ್ clerk ಕೂಡ
ಮುಂದಿನವರನ್ನು ಕರೆಯುವ ಮೊದಲು ಹೀಗೆಯೇ ಯಾರ ಸರದಿ ಎಂದು ನೋಡುತ್ತಾರೆ.

## ಇದು ಎಷ್ಟು ವೇಗವಾಗಿದೆ?

Queue ಎಷ್ಟೇ ಉದ್ದವಿದ್ದರೂ, ಪ್ರತಿ operation ಸ್ವಲ್ಪ ಲೆಕ್ಕ ಮಾಡಿ ಒಂದೇ box ಅನ್ನು ಮುಟ್ಟುತ್ತದೆ. ಆದ್ದರಿಂದ
ಎಲ್ಲಕ್ಕೂ ಒಂದೇ ರೀತಿಯ ಕಡಿಮೆ ಸಮಯ ಸಾಕು, `O(1)`. ನಾವು circle ವಿಧಾನವನ್ನು ಬಳಸುವುದು ಇದೇ ಕಾರಣಕ್ಕೆ: "box 0
ನಿಂದ ತೆಗೆದು ಎಲ್ಲವನ್ನೂ ಸರಿಸುವ" ವಿಧಾನದಲ್ಲಿ ಪ್ರತಿ dequeue ಗೆ `O(n)` ಬೇಕು.

| Operation | ಇದು ಏನು ಮಾಡುತ್ತದೆ | Time |
|---|---|---|
| `enqueue` | rear ನಲ್ಲಿ value ಸೇರಿಸುವುದು | `O(1)` |
| `dequeue` | front ನಲ್ಲಿರುವ value ತೆಗೆಯುವುದು | `O(1)` |
| `peek` | front value ನೋಡುವುದು | `O(1)` |
| `isEmpty` | `count` ನ value `0` ಹೌದೇ ಎಂದು ನೋಡುವುದು | `O(1)` |
| ಒಂದು value ಹುಡುಕುವುದು | values ಅನ್ನು ಒಂದೊಂದಾಗಿ ನೋಡುವುದು | `O(n)` |

`n` values ಗೆ ಜಾಗ ಇರುವ queue `n` boxes ಬಳಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದಕ್ಕೆ `O(n)` memory ಬೇಕು.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **ಸುತ್ತಿಸಲು ಮರೆಯುವುದು.** `(front + 1) % capacity` ಬದಲು `front + 1` ಬರೆದರೆ, ಕೆಲವು operations ನಂತರ
  ನೀವು array ಯ ಕೊನೆಯನ್ನು ದಾಟಿ ಹೋಗುತ್ತೀರಿ.
- **ತುಂಬಿದ ಮತ್ತು ಖಾಲಿ queue ಗಳನ್ನು ಗೊಂದಲ ಮಾಡಿಕೊಳ್ಳುವುದು.** ನೀವು `front` ಮತ್ತು `rear` ಮಾತ್ರ ಇಟ್ಟರೆ,
  ಎರಡೂ ಸ್ಥಿತಿಗಳು ಒಂದೇ ರೀತಿ ಕಾಣಬಹುದು. `count` ಇಡಿ, ಅಥವಾ ಒಂದು box ಅನ್ನು ಯಾವಾಗಲೂ ಖಾಲಿ ಬಿಡಿ.
- **ತಪ್ಪು ತುದಿಯಿಂದ ತೆಗೆಯುವುದು.** Values front ನಿಂದ ಹೊರಹೋಗುತ್ತವೆ. ನಿಮ್ಮ `dequeue` *ಅತ್ಯಂತ ಹೊಸ*
  value ಅನ್ನು return ಮಾಡಿದರೆ, ನೀವು ತಿಳಿಯದೆ stack ಕಟ್ಟಿದ್ದೀರಿ.
- **ಪ್ರತಿ dequeue ನಲ್ಲೂ ಎಲ್ಲಾ values ಸರಿಸುವುದು.** ಇದು ಕೆಲಸ ಮಾಡುತ್ತದೆ, ಆದರೆ `O(1)` operation ಅನ್ನು
  `O(n)` ಆಗಿಸುತ್ತದೆ. JavaScript ನಲ್ಲಿ `array.shift()` ಮತ್ತು PHP ಯಲ್ಲಿ `array_shift()` ನಿಖರವಾಗಿ ಇದನ್ನೇ ಮಾಡುತ್ತವೆ.

## ಇದು ಎಲ್ಲಿ ಬಳಕೆಯಾಗುತ್ತದೆ?

- **Printer queues**, ಮೇಲೆ ನೋಡಿದಂತೆ.
- **CPU scheduling.** Processor ನಲ್ಲಿ ತಮ್ಮ ಸರದಿಗಾಗಿ ಕಾಯುತ್ತಿರುವ programs ಅನ್ನು operating system queues
  ನಲ್ಲಿ ಇಡುತ್ತದೆ.
- **Breadth-first search** ಒಂದು graph ಅಥವಾ maze ಅನ್ನು ಒಂದೊಂದೇ level ಆಗಿ ಹುಡುಕುತ್ತದೆ, ಇನ್ನೂ ಭೇಟಿ
  ನೀಡಬೇಕಾದ ಜಾಗಗಳನ್ನು ಒಂದು queue ನಲ್ಲಿ ಇಡುತ್ತದೆ.
- Apps ಮತ್ತು servers ನಡುವಿನ **messages** queues ನಲ್ಲಿ ಕಾಯುತ್ತವೆ, ಆದ್ದರಿಂದ ಒಂದು ಕಡೆ busy ಆಗಿದ್ದರೂ
  ಏನೂ ಕಳೆದುಹೋಗುವುದಿಲ್ಲ.
- **Video ಮತ್ತು music buffering**: stream ನ ಮುಂದಿನ ಭಾಗಗಳು ಒಂದು queue ನಲ್ಲಿ ಕಾಯುತ್ತವೆ.

   values ಅನ್ನು ಹೊಸ array ಗೆ queue ಕ್ರಮದಲ್ಲಿ, `front` ನಿಂದ ಶುರು ಮಾಡಿ copy ಮಾಡಿ.
