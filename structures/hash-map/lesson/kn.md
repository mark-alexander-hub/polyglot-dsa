**Hash map** ಜೋಡಿಗಳನ್ನು ಇಡುತ್ತದೆ: ಒಂದು **key** ಮತ್ತು ಅದಕ್ಕೆ ಸೇರಿದ **value**, ಒಂದು ಪದ ಮತ್ತು ಅದರ ಅರ್ಥದಂತೆ,
ಅಥವಾ ಒಂದು ತಿಂಡಿ ಮತ್ತು ಅದರ ಬೆಲೆಯಂತೆ. ಅದಕ್ಕೆ key ಕೊಟ್ಟರೆ, ಉಳಿದೆಲ್ಲವನ್ನೂ ಹುಡುಕದೆ, ಒಂದೇ ಜಿಗಿತದಲ್ಲಿ
value ಅನ್ನು ನಿಮ್ಮ ಕೈಗೆ ಕೊಡುತ್ತದೆ. Python ನ `dict`, Java ದ `HashMap`, C++ ನ `unordered_map`,
JavaScript ನ `Map` ಮತ್ತು PHP ಯ associative arrays, ಇವೆಲ್ಲದರ ಹಿಂದೆ ಇರುವ structure ಇದೇ. ಕೆಲವು
ಪುಸ್ತಕಗಳು ಇದನ್ನು **hash table** ಅಥವಾ **dictionary** ಎನ್ನುತ್ತವೆ.

ಇದರ ಗುಟ್ಟು ಒಂದು **hash function**: ಯಾವುದೇ key ಅನ್ನು ಒಂದು ಸಂಖ್ಯೆಯಾಗಿ ಬದಲಿಸುವ ಒಂದು ಚುರುಕಾದ ಲೆಕ್ಕ, ಮತ್ತು
ಆ ಸಂಖ್ಯೆ ಆ ಜೋಡಿ ನಿಖರವಾಗಿ ಎಲ್ಲಿ ಇದೆ ಎಂದು ಹೇಳುತ್ತದೆ.

## ನಿಜ ಜೀವನದಲ್ಲಿ

Post office ನ ಪತ್ರ ವಿಂಗಡಿಸುವ rack ಅನ್ನು ಕಲ್ಪಿಸಿಕೊಳ್ಳಿ: `0`, `1`, `2`, `3` ಎಂದು number ಹಾಕಿದ **ಗೂಡುಗಳು**
ಇರುವ ಒಂದು ಮರದ ಹಲಗೆ. ಬರುವ ಪ್ರತಿ ಪತ್ರವೂ ಯಾವುದಾದರೂ ಒಂದು ಗೂಡಿಗೆ ಹೋಗಬೇಕು, ಮತ್ತು ವಿಂಗಡಿಸುವವರು ಅದನ್ನು
ಆರಿಸಲು ಒಂದು ನಿಗದಿತ ನಿಯಮ ಬಳಸುತ್ತಾರೆ: ಉದಾಹರಣೆಗೆ, ಲಕೋಟೆಯ ಮೇಲಿನ ಹೆಸರಿನ ಅಕ್ಷರಗಳನ್ನು ಕೂಡಿಸಿ, ಗೂಡುಗಳ
ಸಂಖ್ಯೆಯಿಂದ ಭಾಗಿಸಿದಾಗ ಉಳಿಯುವ ಶೇಷವನ್ನು ತೆಗೆದುಕೊಳ್ಳುವುದು. ಯೋಚನೆ ಇಲ್ಲ, ಹುಡುಕಾಟ ಇಲ್ಲ, ಪ್ರತಿ ಬಾರಿಯೂ ಅದೇ
ಉತ್ತರ.

ಯಾರಾದರೂ "*tea* ಗೆ ಪತ್ರ ಇದೆಯೇ?" ಎಂದು ಕೇಳಿದಾಗ, ವಿಂಗಡಿಸುವವರು ಅದೇ ಲೆಕ್ಕ ಮಾಡಿ, ನೇರವಾಗಿ ಆ ಒಂದು ಗೂಡಿಗೆ
ಹೋಗಿ, ಅದರಲ್ಲಿರುವ ಕೆಲವೇ ಲಕೋಟೆಗಳನ್ನು ತಿರುವಿ ನೋಡುತ್ತಾರೆ. ಬೇರೆ ಹೆಸರುಗಳ ಪತ್ರಗಳನ್ನು ಮುಟ್ಟುವುದೇ ಇಲ್ಲ.
Hash map ಎಂದರೆ ಇದೇ:

- **ನಿಯಮ** ಎಂದರೆ hash function.
- **ಗೂಡುಗಳು** ಎಂದರೆ **buckets**.
- ಎರಡು ಹೆಸರುಗಳು ಒಂದೇ ಗೂಡಿಗೆ ಬೀಳುವುದು **collision**. ಆ ಲಕೋಟೆಗಳು ಆ ಗೂಡಿನಲ್ಲಿ ಒಟ್ಟಿಗೆ ಕೂರುತ್ತವೆ ಅಷ್ಟೇ,
  ಮತ್ತು ಒಂದನ್ನು ಹುಡುಕುವಾಗ ಉಳಿದವನ್ನು ದಾಟಿ ನೋಡಬೇಕು.
- ಗೂಡುಗಳು ಕಿಕ್ಕಿರಿದಾಗ, post office **ದೊಡ್ಡ rack** ತಂದು, ಹೊಸ ಗೂಡುಗಳ ಸಂಖ್ಯೆಯೊಂದಿಗೆ ಪ್ರತಿ ಪತ್ರವನ್ನೂ
  ಮತ್ತೆ ವಿಂಗಡಿಸುತ್ತದೆ.

ಇದೇ idea ನಿಮಗೆ dictionary ಯಲ್ಲಿ ಸಿಗುತ್ತದೆ (ಮೊದಲ ಅಕ್ಷರ ನಿಮ್ಮನ್ನು ಸರಿಯಾದ ಭಾಗಕ್ಕೆ ಕಳಿಸುತ್ತದೆ),
library ಯಲ್ಲಿ ಸಿಗುತ್ತದೆ (shelf number ಪುಸ್ತಕದ ಮೇಲೆಯೇ ಮುದ್ರಿತವಾಗಿರುತ್ತದೆ), ಮತ್ತು ನಿಮ್ಮ roll number
ನಿಮ್ಮ seat ಎಲ್ಲಿ ಎಂದು ಹೇಳುವ exam hall ನಲ್ಲಿ ಸಿಗುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

Hash map ಎಂದರೆ **buckets** ಗಳ ಒಂದು array. ಪ್ರತಿ bucket ಒಂದು **chain** ಅನ್ನು, ಅಂದರೆ entries ಗಳ ಒಂದು
ಪುಟ್ಟ linked list ಅನ್ನು ಹಿಡಿದಿಟ್ಟುಕೊಳ್ಳುತ್ತದೆ, ಮತ್ತು ಪ್ರತಿ entry ಒಂದು key, ಅದರ value, ಮತ್ತು chain ನಲ್ಲಿ
ಮುಂದಿನ entry ಯಾವುದು ಎಂದು ನೆನಪಿಟ್ಟುಕೊಳ್ಳುತ್ತದೆ. Collisions ಅನ್ನು ನಿಭಾಯಿಸುವ ಈ ದಾರಿಗೆ **chaining**
ಎನ್ನುತ್ತಾರೆ.

ನಮ್ಮ hash function ಅನ್ನು ಬೇಕೆಂದೇ ಸರಳವಾಗಿ ಇಟ್ಟಿದ್ದೇವೆ: key ನ character codes ಗಳನ್ನು ಕೂಡಿಸುವುದು. `t` ನ
code `116`, `e` ನದು `101`, `a` ನದು `97`, ಆದ್ದರಿಂದ `tea` ನ hash `314`. Buckets ಸಂಖ್ಯೆಯಿಂದ ಭಾಗಿಸಿ
ಶೇಷವನ್ನು ಇಟ್ಟುಕೊಂಡರೆ bucket ಸಿಗುತ್ತದೆ: `4` buckets ಇದ್ದರೆ `314 % 4 = 2`, ಆದ್ದರಿಂದ `tea` bucket `2`
ರಲ್ಲಿ ಇರುತ್ತದೆ. ಯಾವುದೇ key, ಎಷ್ಟೇ ಉದ್ದ ಇರಲಿ, ಒಂದು ಸಣ್ಣ index ಆಗುತ್ತದೆ.

`idli` ಯ hash `418`, ಮತ್ತು `418 % 4` ಕೂಡ `2`. ಇದೇ collision: `idli` ಮತ್ತು `tea` bucket `2` ಅನ್ನು
ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ, ಒಂದರ ಹಿಂದೆ ಒಂದು chain ಆಗಿ. Collisions ಸಹಜ. Hash map ಮಾಡಬೇಕಾದದ್ದು chains ಗಳನ್ನು
ಚಿಕ್ಕದಾಗಿ ಇಡುವುದು ಮಾತ್ರ.

ನಾವು `count`, ಅಂದರೆ ಇಟ್ಟಿರುವ keys ಸಂಖ್ಯೆ, ಮತ್ತು `bucketCount`, ಅಂದರೆ buckets ಸಂಖ್ಯೆ, ಇಟ್ಟುಕೊಳ್ಳುತ್ತೇವೆ.
ಅವುಗಳ ಅನುಪಾತ, `count / bucketCount`, **load factor**: table ಎಷ್ಟು ಕಿಕ್ಕಿರಿದಿದೆ ಎಂಬುದು.

> **ನಾವೇ ಏಕೆ ಕಟ್ಟಬೇಕು?** ಪ್ರತಿ ಭಾಷೆಯಲ್ಲೂ ಒಂದು ಸಿದ್ಧವಾಗಿ ಸಿಗುತ್ತದೆ: Python ನಲ್ಲಿ `dict`, C++ ನಲ್ಲಿ
> `std::unordered_map`, Java ದಲ್ಲಿ `HashMap`, JavaScript ನಲ್ಲಿ `Map` (ಮತ್ತು ಪ್ರತಿ ಸಾಮಾನ್ಯ object ಕೂಡ),
> PHP ಯಲ್ಲಿ string keys ಇರುವ arrays. ನೀವು ಬಳಸುವುದು ಅವನ್ನೇ. ಆದರೆ ಒಮ್ಮೆ ನೀವೇ ಕಟ್ಟಿದರೆ `get` ಏಕೆ ವೇಗ,
> collision ಗೆ ಎಷ್ಟು ಬೆಲೆ, ಮತ್ತು ಕೆಟ್ಟ hash function ಅದನ್ನು ಹೇಗೆ ತೆವಳುವಂತೆ ಮಾಡಬಲ್ಲದು ಎಂದು ನಿಮಗೆ
> ಗೊತ್ತಾಗುತ್ತದೆ. Interview ಗಳಲ್ಲಿ ಕೇಳುವುದು ನಿಖರವಾಗಿ ಇದನ್ನೇ.

## Operations

Hash map ಗೆ ಮೂರು ಮುಖ್ಯ operations ಇವೆ, ಮತ್ತು ಪ್ರತಿಯೊಂದೂ ಒಂದೇ ರೀತಿ ಶುರುವಾಗುತ್ತದೆ: key ಅನ್ನು hash
ಮಾಡಿ, bucket ಹುಡುಕಿ. ಯಾವಾಗಲೂ ಆ bucket ನ chain ಅನ್ನು ಮಾತ್ರ ನೋಡಲಾಗುತ್ತದೆ.

### put: ಒಂದು key ಅನ್ನು ಅದರ value ಜೊತೆ ಇಡುವುದು

1. Key ಅನ್ನು hash ಮಾಡಿ ಅದರ bucket ಗೆ ಹೋಗಿ.
2. Chain ನಲ್ಲಿ ನಡೆಯಿರಿ. Key ಆಗಲೇ ಅಲ್ಲಿದ್ದರೆ, ಅದರ value ಅನ್ನು ಬದಲಿಸಿ ನಿಲ್ಲಿಸಿ. Hash map ನಲ್ಲಿ ಒಂದು
   key ಒಮ್ಮೆ ಮಾತ್ರ ಇರುತ್ತದೆ.
3. ಸರಾಸರಿ ಪ್ರತಿ bucket ನಲ್ಲಿ ಆಗಲೇ ಒಂದು key ಇದ್ದರೆ (`count` ಮತ್ತು `bucketCount` ಸಮವಾಗಿದ್ದರೆ), table
   ಕಿಕ್ಕಿರಿಯುತ್ತಿದೆ: ಮೊದಲು ಅದನ್ನು **ಬೆಳೆಸಿ** (ಕೆಳಗೆ ನೋಡಿ).
4. ಹೊಸ entry ಮಾಡಿ ಅದನ್ನು chain ನ **ಮುಂಭಾಗದಲ್ಲಿ**, ಅಲ್ಲಿ ಏನಿತ್ತೋ ಅದರ ಮುಂದೆ ಇಡಿ. `count` ಗೆ ಒಂದು
   ಸೇರಿಸಿ.

<!-- code: put -->

Demo ದಲ್ಲಿ, `put dosa=40` ಖಾಲಿ bucket `3` ಕ್ಕೆ ಹೋಗುತ್ತದೆ. `put idli=30` ಗೆ bucket `2` ರಲ್ಲಿ ಆಗಲೇ `tea`
ಸಿಗುತ್ತದೆ, ಆದ್ದರಿಂದ chain `idli=30 -> tea=10` ಆಗುತ್ತದೆ. `put tea=12` ಗೆ ಆ chain ನಲ್ಲಿ `tea` ಸಿಗುತ್ತದೆ,
ಮತ್ತು ಅದು value ಅನ್ನು ಮಾತ್ರ ಬದಲಿಸುತ್ತದೆ.

### get: ಒಂದು key ಗೆ value ಹುಡುಕುವುದು

1. Key ಅನ್ನು hash ಮಾಡಿ ಅದರ bucket ಗೆ ಹೋಗಿ.
2. Keys ಗಳನ್ನು ಹೋಲಿಸುತ್ತಾ chain ನಲ್ಲಿ ನಡೆಯಿರಿ. Key ಹೊಂದಿದ ತಕ್ಷಣ value ಅನ್ನು return ಮಾಡಿ.
3. ಹೊಂದಿಕೆ ಸಿಗದೆ chain ಮುಗಿದರೆ, ಆ key map ನಲ್ಲಿ ಇಲ್ಲವೇ ಇಲ್ಲ. ಬೇರೆ ಯಾವ bucket ಕೂಡ ಅದನ್ನು
   ಹಿಡಿದಿರಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದ್ದರಿಂದ ಹುಡುಕಲು ಇನ್ನೇನೂ ಉಳಿದಿಲ್ಲ.

<!-- code: get -->

`get idli` ನೇರವಾಗಿ bucket `2` ಕ್ಕೆ ಹೋಗಿ ಮುಂಭಾಗದಲ್ಲೇ `idli` ಯನ್ನು ಕಾಣುತ್ತದೆ: ಒಂದೇ ಹೋಲಿಕೆ. `get puri` ಯ
hash `448`, `448 % 4 = 0`, ಮತ್ತು bucket `0` ರಲ್ಲಿ `vada` ಮಾತ್ರ ಇದೆ, ಆದ್ದರಿಂದ ಒಂದು ಹೋಲಿಕೆಯ ನಂತರ `puri`
ಇಲ್ಲಿ ಇಲ್ಲ ಎಂದು ನಮಗೆ ಗೊತ್ತಾಗುತ್ತದೆ.

### remove: ಒಂದು key ಅನ್ನು ಹೊರತೆಗೆಯುವುದು

1. Key ಅನ್ನು hash ಮಾಡಿ ಅದರ bucket ಗೆ ಹೋಗಿ.
2. **ಹಿಂದಿನ** entry ಯನ್ನು ನೆನಪಿಟ್ಟುಕೊಳ್ಳುತ್ತಾ chain ನಲ್ಲಿ ನಡೆಯಿರಿ.
3. Key ಹೊಂದಿದಾಗ, ಆ entry ಯನ್ನು ಬಿಡಿಸಿ: ಹಿಂದಿನ entry ಯನ್ನು (ಅಥವಾ ಅದು ಮೊದಲನೆಯದಾಗಿದ್ದರೆ bucket
   ಅನ್ನೇ) ಅದರ ಮುಂದಿನದರ ಕಡೆಗೆ ತೋರಿಸಿ. `count` ನಿಂದ ಒಂದು ಕಳೆಯಿರಿ.

### Table ಅನ್ನು ಬೆಳೆಸುವುದು

`count` `bucketCount` ಅನ್ನು ತಲುಪಿದಾಗ, chains ಉದ್ದವಾಗಲು ಹೊರಟಿವೆ ಎಂದರ್ಥ, ಆದ್ದರಿಂದ table ತನ್ನ buckets
ಸಂಖ್ಯೆಯನ್ನು ದುಪ್ಪಟ್ಟು ಮಾಡಿಕೊಳ್ಳುತ್ತದೆ. ದುಪ್ಪಟ್ಟು ಮಾಡಿದಾಗ hash ಲೆಕ್ಕದಲ್ಲಿನ `%` ಬದಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಪ್ರತಿ
key ಅನ್ನೂ ಮತ್ತೆ ಇಡಬೇಕು: `vada` ದ hash `412`, ಅದು `4` ರಲ್ಲಿ bucket `0` ಆಗಿತ್ತು, ಆದರೆ `8` ರಲ್ಲಿ bucket
`4`. ಇದಕ್ಕೆ **rehashing** ಎನ್ನುತ್ತಾರೆ.

Entries ಗಳನ್ನು ಸರಿಸಿದಾಗ ಒಂದು bucket ನ ಒಳಗಿನ ಅವುಗಳ ಕ್ರಮ ಬದಲಾಗಬಹುದು. ಅದು ಪರವಾಗಿಲ್ಲ: hash map ಯಾವುದೇ
ಕ್ರಮದ ಮಾತು ಕೊಟ್ಟೇ ಇಲ್ಲ.

## ಇದು ಎಷ್ಟು ವೇಗವಾಗಿದೆ?

ಒಳ್ಳೆಯ hash function ಮತ್ತು ಬೇಕಾದಾಗ ಬೆಳೆಯುವ table ಇದ್ದರೆ, ಪ್ರತಿ chain ನಲ್ಲೂ ಸುಮಾರು ಒಂದು entry
ಇರುತ್ತದೆ. ಆದ್ದರಿಂದ `put`, `get` ಮತ್ತು `remove` ಮಾಡುವುದು ಒಂದು hash ಲೆಕ್ಕ, ಒಂದು array lookup, ಮತ್ತು
ಒಂದೆರಡು ಹೋಲಿಕೆ: ಎಷ್ಟು keys ಇಟ್ಟಿದ್ದರೂ `O(1)`. ನೂರು keys ಇರಲಿ, ಹತ್ತು ಕೋಟಿ ಇರಲಿ, ಅದೇ ವೇಗ. ಅದಕ್ಕೇ
hash maps ಎಲ್ಲೆಡೆ ಇವೆ.

| Operation | ಇದು ಏನು ಮಾಡುತ್ತದೆ | Time |
|---|---|---|
| `put` | hash ಮಾಡಿ, bucket ಗೆ ಹೋಗಿ, ಸಣ್ಣ chain ನಲ್ಲಿ ನಡೆಯುವುದು | ಸರಾಸರಿ `O(1)` |
| `get` | hash ಮಾಡಿ, bucket ಗೆ ಹೋಗಿ, ಸಣ್ಣ chain ನಲ್ಲಿ ನಡೆಯುವುದು | ಸರಾಸರಿ `O(1)` |
| `remove` | hash ಮಾಡಿ, bucket ಗೆ ಹೋಗಿ, ಒಂದು entry ಬಿಡಿಸುವುದು | ಸರಾಸರಿ `O(1)` |
| `grow` | ಪ್ರತಿ key ಅನ್ನೂ ಮತ್ತೆ ಇಡುವುದು | `O(n)`, ಆದರೆ ಅಪರೂಪ |
| `keys` | ಪ್ರತಿ bucket ಮತ್ತು ಪ್ರತಿ chain ಗೂ ಭೇಟಿ ಕೊಡುವುದು | `O(n)` |

ಆ table ನಲ್ಲಿ ಎರಡು ಎಚ್ಚರಿಕೆಗಳು ಅಡಗಿವೆ. ಮೊದಲನೆಯದು, "ಸರಾಸರಿ": hash function ಪ್ರತಿ key ಅನ್ನೂ ಒಂದೇ
bucket ಗೆ ಕಳಿಸಿದರೆ, map ಒಂದು ಉದ್ದನೆಯ chain ಆಗಿ, ಎಲ್ಲವೂ `O(n)` ಆಗುತ್ತದೆ. ಎರಡನೆಯದು, ಬೆಳೆಸುವುದಕ್ಕೆ ಆ
ಕ್ಷಣದಲ್ಲಿ `O(n)` ಖರ್ಚಾಗುತ್ತದೆ, ಆದರೆ ಅದು keys ಸಂಖ್ಯೆ ದುಪ್ಪಟ್ಟಾದ ಮೇಲೆ ಮಾತ್ರ ಆಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಎಲ್ಲಾ
puts ಮೇಲೆ ಹಂಚಿದರೆ ಪ್ರತಿ `put` ಗೆ ಖರ್ಚು ಈಗಲೂ ಸ್ಥಿರವೇ.

`n` keys ಇರುವ hash map entries ಗಾಗಿ `O(n)` memory, ಜೊತೆಗೆ buckets ಗಳ ಒಂದು array ಬಳಸುತ್ತದೆ.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **ಒಂದು ಕ್ರಮವನ್ನು ನಿರೀಕ್ಷಿಸುವುದು.** Demo ದಲ್ಲಿ `keys` `coffee, tea, vada, dosa` ಎಂದು return
  ಮಾಡುತ್ತದೆ: ಅದು bucket ಕ್ರಮ, ಸೇರಿಸಿದ ಕ್ರಮ ಅಲ್ಲ, ಮತ್ತು table ಬೆಳೆದಾಗ ಅದು ಬದಲಾಗುತ್ತದೆ. ಕ್ರಮ ಬೇಕೇ?
  Map ನ ಪಕ್ಕ ಒಂದು list ಇಟ್ಟುಕೊಳ್ಳಿ, ಅಥವಾ ಒಂದು sorted structure ಬಳಸಿ.
- **ದುರ್ಬಲ hash function.** ನಮ್ಮ ಅಕ್ಷರಗಳ ಮೊತ್ತ ಪ್ರತಿ anagram ಅನ್ನೂ ಒಂದೇ bucket ಗೆ ಕಳಿಸುತ್ತದೆ:
  `listen`, `silent` ಮತ್ತು `enlist` ಎಲ್ಲವೂ `655` ಕ್ಕೆ hash ಆಗುತ್ತವೆ. ನಿಜವಾದ hash functions characters
  ಗಳನ್ನು ಕಲಸುತ್ತವೆ, ಉದಾಹರಣೆಗೆ ಪ್ರತಿ character ಗೂ `hash = hash * 31 + code`, ಆಗ ಕ್ರಮವೂ ಮುಖ್ಯವಾಗುತ್ತದೆ.
- **ಎಂದೂ ಬೆಳೆಸದೆ ಇರುವುದು.** `grow` ಇಲ್ಲದಿದ್ದರೆ ಪ್ರತಿ key ಜೊತೆ chains ಉದ್ದವಾಗುತ್ತಾ ಹೋಗಿ, `get`
  ಸದ್ದಿಲ್ಲದೆ `O(1)` ನಿಂದ `O(n)` ಕಡೆಗೆ ಜಾರುತ್ತದೆ.
- **`put` ಒಂದು update ಆಗಿರಬಹುದು ಎಂದು ಮರೆಯುವುದು.** ಒಂದು key ಒಮ್ಮೆ ಮಾತ್ರ ಇರುತ್ತದೆ. `put` ಮೊದಲು ಇರುವ
  key ಅನ್ನು ಪರಿಶೀಲಿಸದಿದ್ದರೆ, map ನಲ್ಲಿ `tea` ಗೆ ಎರಡು entries ಆಗಿ, `get` ಮೊದಲು ಸಿಕ್ಕಿದ್ದನ್ನು return
  ಮಾಡುತ್ತದೆ.
- **ಇಟ್ಟ ಮೇಲೆ key ಅನ್ನು ಬದಲಿಸುವುದು.** Bucket ಅನ್ನು key ನ ಹಳೆಯ value ಯಿಂದ ಆರಿಸಲಾಗಿತ್ತು, ಆದ್ದರಿಂದ ಆ
  entry ಇನ್ನು ಸಿಗುವುದೇ ಇಲ್ಲ. ಎಂದೂ ಬದಲಾಗದ keys ಬಳಸಿ: strings ಮತ್ತು numbers, lists ಅಲ್ಲ.
- **"ಸಿಗಲಿಲ್ಲ" ಮತ್ತು ಇಟ್ಟಿರುವ ಖಾಲಿಯನ್ನು ಬೆರೆಸುವುದು.** Key ಇಲ್ಲದಿದ್ದಾಗ `get` `None`, `null` ಅಥವಾ
  `undefined` return ಮಾಡುತ್ತದೆ. ನೀವು ಅಂತಹ value ಅನ್ನೂ ಇಟ್ಟರೆ, ಎರಡನ್ನೂ ಬೇರ್ಪಡಿಸಲು ಆಗುವುದಿಲ್ಲ; ಒಂದು key
  ಇದೆಯೇ ಎಂದು ಕೇಳಲು `contains` ಬಳಸಿ.

## ಇದು ಎಲ್ಲಿ ಬಳಕೆಯಾಗುತ್ತದೆ?

- ಪ್ರತಿ ಭಾಷೆಯಲ್ಲೂ **dictionaries ಮತ್ತು objects**: `prices["dosa"]`, `user.name`, JSON.
- **ಎಣಿಸುವುದು:** ಒಂದು ಪುಸ್ತಕದಲ್ಲಿ ಪ್ರತಿ ಪದ ಎಷ್ಟು ಬಾರಿ ಬರುತ್ತದೆ, ಪ್ರತಿ product ಎಷ್ಟು ಮಾರಾಟವಾಗುತ್ತದೆ,
  ಪ್ರತಿ IP address ಎಷ್ಟು ಬಾರಿ connect ಆಗುತ್ತದೆ. Key ಎಂದರೆ ಆ ವಸ್ತು, value ಎಂದರೆ ಅದರ ಎಣಿಕೆ.
- **Caches:** ದುಬಾರಿ ಪ್ರಶ್ನೆಯ ಉತ್ತರವನ್ನು (ಒಂದು web page, ಒಂದು database row) ಅದರ key ಅಡಿಯಲ್ಲಿ ಇಟ್ಟು,
  ಮುಂದಿನ ಬಾರಿ ತಕ್ಷಣ return ಮಾಡುವುದು.
- **Sets:** keys ಗಳನ್ನು ಮಾತ್ರ ಇಟ್ಟುಕೊಳ್ಳುವ hash map "ಇದನ್ನು ನಾನು ಮೊದಲು ನೋಡಿದ್ದೇನೆಯೇ?" ಎಂಬುದಕ್ಕೆ `O(1)`
  ನಲ್ಲಿ ಉತ್ತರ ಕೊಡುತ್ತದೆ. Duplicates ತೆಗೆಯುವುದು ಮತ್ತು ಒಂದು search ನಲ್ಲಿ ಭೇಟಿ ಕೊಟ್ಟ ಜಾಗಗಳನ್ನು
  ನೆನಪಿಡುವುದು ಹೀಗೆಯೇ.
- Databases ಮತ್ತು search engines ಗಳಲ್ಲಿ **indexes**, ಆಗ ಒಂದು lookup ಇಡೀ table ಅನ್ನು ಓದಬೇಕಾಗಿಲ್ಲ.
- **ನಿಮ್ಮ phone ನ contacts**, DNS (ಹೆಸರಿನಿಂದ address), compilers (variable ನ ಹೆಸರಿನಿಂದ ಅದರ type),
  ಮತ್ತು "ಒಂದು target ಗೆ ಕೂಡುವ ಎರಡು numbers ಹುಡುಕಿ" ಎಂಬ ಪ್ರಸಿದ್ಧ interview ಪ್ರಶ್ನೆ.

## ಇವುಗಳನ್ನು ಮಾಡಿ ನೋಡಿ

1. `4` buckets ಇಟ್ಟುಕೊಂಡು, `chai`, `puri`, `upma` ಮತ್ತು `poha` ಗಳ bucket ಅನ್ನು ಕೈಯಲ್ಲೇ ಲೆಕ್ಕ ಮಾಡಿ
   (character codes ಕೂಡಿಸಿ, ನಂತರ `% 4`), ಆಮೇಲೆ playground ನಲ್ಲಿ ನಿಮ್ಮನ್ನು ನೀವೇ ಪರಿಶೀಲಿಸಿಕೊಳ್ಳಿ.
2. `vada` (`412`) ಮತ್ತು `coffee` (`616`) `4` buckets ಇದ್ದಾಗ collide ಆಗುತ್ತವೆ, ಆದರೆ `8` ಇದ್ದಾಗ ಇಲ್ಲ.
   ಹೀಗೆಯೇ ಮಾಡುವ ಇನ್ನೆರಡು keys ಹುಡುಕಿ.
3. `hashOf` ಅನ್ನು ಪ್ರತಿ character ಗೂ `hash = hash * 31 + code` ಎಂದು ಬದಲಿಸಿ. `listen` ಮತ್ತು `silent`
   ಈಗಲೂ collide ಆಗುತ್ತವೆಯೇ? Demo ದ keys ಈಗ ಯಾವ buckets ಗಳಲ್ಲಿ ಬೀಳುತ್ತವೆ?
4. ಒಂದು ವಾಕ್ಯವನ್ನು ಪದಗಳಾಗಿ ಒಡೆದು, ಪ್ರತಿ ಪದದಿಂದ ಅದು ಎಷ್ಟು ಬಾರಿ ಬರುತ್ತದೆ ಎಂಬ ಸಂಖ್ಯೆಗೆ ಒಂದು hash map
   return ಮಾಡುವ `countWords(text)` ಬರೆಯಿರಿ.
5. Table ನಲ್ಲಿನ ಅತಿ ಉದ್ದದ chain ನ ಉದ್ದವನ್ನು return ಮಾಡುವ `longestChain()` ಎಂಬ method ಸೇರಿಸಿ. `20`
   keys ಹಾಕಿ ಅದು ಏನು ಹೇಳುತ್ತದೆ ನೋಡಿ. ನಂತರ ಅಭ್ಯಾಸ 3 ರ `31` hash ಬಳಸಿ ಹೋಲಿಸಿ.
