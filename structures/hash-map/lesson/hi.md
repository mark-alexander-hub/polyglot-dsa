**Hash map** जोड़ियाँ रखता है: एक **key** और उसकी **value**, जैसे कोई शब्द और उसका मतलब, या कोई
dish और उसका दाम। उसे key दीजिए, और वो एक ही छलाँग में आपको value थमा देता है, बाकी सब कुछ
देखे बिना। यही structure Python के `dict`, Java के `HashMap`, C++ के `unordered_map`,
JavaScript के `Map` और PHP के associative arrays के पीछे है। कुछ किताबें इसे **hash table** या
**dictionary** भी कहती हैं।

इसकी तरकीब है एक **hash function**: एक झटपट हिसाब जो किसी भी key को एक number में बदल देता है,
और वही number ठीक-ठीक बताता है कि जोड़ी कहाँ रखी है।

## असल ज़िंदगी में

किसी post office के sorting rack की कल्पना कीजिए: लकड़ी का एक board जिसमें खाने बने हैं, और
उन पर number लिखे हैं, `0`, `1`, `2`, `3`। जो भी चिट्ठी आती है, उसे किसी एक खाने में जाना है,
और sorter उसे चुनने के लिए एक तय नियम इस्तेमाल करता है: मान लीजिए, लिफ़ाफ़े पर लिखे नाम के अक्षरों
को जोड़िए और खानों की संख्या से भाग देकर बचा हुआ (remainder) ले लीजिए। न सोचना, न ढूँढना, हर बार
वही जवाब।

जब कोई पूछता है "क्या *tea* के नाम की कोई चिट्ठी है?", तो sorter वही जोड़ करता है, सीधे उसी
एक खाने तक जाता है और उसमें रखे गिने-चुने लिफ़ाफ़े पलट लेता है। दूसरे नामों की चिट्ठियों को हाथ
भी नहीं लगाना पड़ता। यही hash map है:

- **नियम** hash function है।
- **खाने** **buckets** हैं।
- दो नामों का एक ही खाने में आ जाना **collision** है। लिफ़ाफ़े बस उसी खाने में साथ-साथ पड़े
  रहते हैं, और किसी एक को ढूँढने का मतलब है बाकी को पलटते हुए आगे बढ़ना।
- जब खाने भीड़भाड़ वाले हो जाते हैं, तो post office एक **बड़ा rack** ले आता है और हर चिट्ठी को
  खानों की नई संख्या के हिसाब से दोबारा छाँटता है।

यही idea आपको एक dictionary में मिलता है (पहला अक्षर आपको सही हिस्से तक भेज देता है), एक
library में (shelf का number किताब पर छपा होता है), और exam hall में जहाँ आपका roll number
बताता है कि आपकी seat कौन सी है।

## ये काम कैसे करता है

Hash map **buckets** का एक array है। हर bucket में entries की एक **chain** होती है, यानी एक
नन्ही सी linked list, और हर entry को एक key, उसकी value, और chain की अगली entry याद रहती है।
Collisions सँभालने के इस तरीके को **chaining** कहते हैं।

हमारा hash function जानबूझकर आसान रखा गया है: key के characters के codes जोड़ दीजिए। `t` का
code `116` है, `e` का `101` और `a` का `97`, इसलिए `tea` का hash `314` बनता है। buckets की
संख्या से भाग देकर बचा हुआ रखने पर bucket मिल जाता है: `4` buckets के साथ `314 % 4 = 2`,
इसलिए `tea` bucket `2` में रहता है। कोई भी key, चाहे जितनी लंबी हो, एक छोटा सा index बन जाती है।

`idli` का hash `418` है, और `418 % 4` भी `2` ही है। ये collision है: `idli` और `tea` bucket `2`
बाँटते हैं, एक के बाद एक chain में जुड़े हुए। Collisions होना सामान्य बात है। Hash map को बस
chains को छोटा रखना होता है।

हम `count` रखते हैं, यानी रखी हुई keys की गिनती, और `bucketCount`, यानी buckets की संख्या।
इनका अनुपात, `count / bucketCount`, **load factor** है: table कितनी भरी हुई है।

> `std::unordered_map`, Java में `HashMap`, JavaScript में `Map` (और हर साधारण object), PHP
> में string keys वाले arrays। आप उन्हीं का इस्तेमाल करेंगे। लेकिन एक बार खुद बना लेने पर आपको
> पता होता है कि `get` तेज़ क्यों है, collision की कीमत क्या है, और एक खराब hash function इसे
> रेंगने पर क्यों मजबूर कर सकता है। Interview में ठीक यही पूछा जाता है।

## Operations

Hash map के तीन मुख्य operations हैं, और हर एक की शुरुआत एक ही तरह होती है: key को hash
कीजिए, bucket ढूँढिए। सिर्फ़ उसी bucket की chain को कभी देखा जाता है।

### put: एक key को उसकी value के साथ रखना

1. Key को hash कीजिए और उसके bucket तक जाइए।
2. Chain पर चलिए। अगर key पहले से वहाँ है, तो उसकी value बदल दीजिए और रुक जाइए। Hash map में
   एक key सिर्फ़ एक बार आती है।
3. अगर औसतन हर bucket में पहले से एक key है (`count` और `bucketCount` बराबर हैं), तो table
   भीड़भाड़ वाली होने लगी है: पहले उसे **grow** कीजिए (नीचे देखिए)।
4. एक नई entry बनाइए और उसे chain के **सामने** रखिए, जो कुछ पहले से था उसके आगे। `count` में
   एक जोड़ दीजिए।

<!-- code: put -->

Demo में `put dosa=40` खाली bucket `3` में जाता है। `put idli=30` को bucket `2` में `tea` पहले से
मिलता है, इसलिए chain `idli=30 -> tea=10` बन जाती है। `put tea=12` को उसी chain में `tea` मिलता
है और वो सिर्फ़ उसकी value बदलता है।

### get: किसी key की value ढूँढना

1. Key को hash कीजिए और उसके bucket तक जाइए।
2. Chain पर चलते हुए keys की तुलना कीजिए। जैसे ही key मिले, value लौटा दीजिए।
3. अगर chain बिना मिले ख़त्म हो जाए, तो key map में है ही नहीं। कोई और bucket उसे रख ही नहीं
   सकता, इसलिए और कुछ ढूँढना बाकी नहीं रहता।

<!-- code: get -->

`get idli` सीधे bucket `2` तक जाता है और `idli` को सबसे आगे पाता है: एक तुलना। `get puri` का hash
`448` बनता है, `448 % 4 = 0`, और bucket `0` में सिर्फ़ `vada` है, इसलिए एक तुलना के बाद ही हमें
पता चल जाता है कि `puri` यहाँ नहीं है।

### remove: किसी key को निकालना

1. Key को hash कीजिए और उसके bucket तक जाइए।
2. Chain पर चलिए, और **पिछली** entry को याद रखते चलिए।
3. जब key मिल जाए, तो entry को अलग कर दीजिए: पिछली entry को (या bucket को ही, अगर वो पहली थी)
   उसके बाद वाली entry की ओर इशारा करवा दीजिए। `count` में से एक घटा दीजिए।

### Table को बढ़ाना

जब `count` बढ़कर `bucketCount` तक पहुँच जाता है, तो chains लंबी होने ही वाली हैं, इसलिए table
अपने buckets की संख्या दोगुनी कर लेती है। दोगुना करने से hash के हिसाब में `%` बदल जाता है,
इसलिए हर key को दोबारा जगह देनी पड़ती है: `vada` का hash `412` था, जो `4` में से bucket `0` था,
लेकिन `8` में से bucket `4` है। इसे **rehashing** कहते हैं।

जब entries को हटाया जाता है, तो एक bucket के अंदर उनका क्रम बदल सकता है। कोई बात नहीं: hash map
ने कभी किसी क्रम का वादा किया ही नहीं था।

## ये कितना तेज़ है?

एक ठीक-ठाक hash function और समय पर बढ़ने वाली table के साथ हर chain में लगभग एक entry होती है।
तो `put`, `get` और `remove` एक hash का हिसाब, array में एक lookup, और एक-दो तुलनाएँ करते हैं:
`O(1)`, चाहे जितनी keys रखी हों। सौ keys हों या दस करोड़, रफ़्तार वही। इसीलिए hash maps हर
जगह हैं।

| Operation | ये क्या करता है | Time |
|---|---|---|
| `put` | hash, bucket तक जाना, एक छोटी chain पर चलना | औसतन `O(1)` |
| `get` | hash, bucket तक जाना, एक छोटी chain पर चलना | औसतन `O(1)` |
| `remove` | hash, bucket तक जाना, एक entry अलग करना | औसतन `O(1)` |
| `grow` | हर key को दोबारा जगह देना | `O(n)`, लेकिन कभी-कभार |
| `keys` | हर bucket और हर chain देखना | `O(n)` |

इस table में दो चेतावनियाँ छिपी हैं। पहली, "औसतन": अगर hash function हर key को एक ही bucket में
भेज दे, तो पूरा map एक लंबी chain बन जाता है और सब कुछ `O(n)` हो जाता है। दूसरी, बढ़ने में जब
बढ़ना होता है तब `O(n)` लगता है, लेकिन ये तभी होता है जब keys की गिनती दोगुनी हो जाए, इसलिए सारे
puts पर बाँट दें तो हर `put` की कीमत फिर भी constant ही रहती है।

`n` keys वाला hash map entries के लिए `O(n)` memory और buckets का एक array इस्तेमाल करता है।

## आम गलतियाँ

- **किसी क्रम की उम्मीद करना।** Demo में `keys` लौटाता है `coffee, tea, vada, dosa`: bucket के
  क्रम में, उस क्रम में नहीं जिसमें वे जोड़ी गई थीं, और table के बढ़ने पर ये बदल भी जाता है। क्रम
  चाहिए? Map के साथ एक list रखिए, या कोई sorted structure इस्तेमाल कीजिए।
- **एक कमज़ोर hash function।** हमारा अक्षरों का जोड़ हर anagram को एक ही bucket में भेजता है:
  `listen`, `silent` और `enlist` तीनों का hash `655` है। असली hash functions characters को
  घोलकर मिलाते हैं, जैसे हर character के लिए `hash = hash * 31 + code`, ताकि क्रम भी मायने रखे।
- **कभी न बढ़ना।** बिना `grow` के हर key के साथ chains लंबी होती जाती हैं और `get` चुपचाप `O(1)`
  से `O(n)` की ओर खिसकता जाता है।
- **ये भूल जाना कि `put` एक update भी हो सकता है।** एक key एक ही बार आती है। अगर `put` पहले
  से मौजूद key की जाँच पहले नहीं करता, तो map में `tea` की दो entries बन जाती हैं और `get` उनमें
  से जो पहले मिले वही लौटा देता है।
- **रखने के बाद key बदल देना।** Bucket key की पुरानी value से चुना गया था, इसलिए अब entry
  ढूँढी ही नहीं जा सकती। ऐसी keys इस्तेमाल कीजिए जो कभी न बदलें: strings और numbers, lists नहीं।
- **"not found" और रखे हुए "कुछ नहीं" को गड्डमड्ड करना।** Key न मिलने पर `get` `None`, `null` या
  `undefined` लौटाता है। अगर आप ऐसी value भी रखते हैं, तो दोनों में फ़र्क नहीं कर पाएँगे; ये
  पूछने के लिए कि key है या नहीं, `contains` इस्तेमाल कीजिए।

## ये कहाँ काम आता है?

- हर भाषा में **dictionaries और objects**: `prices["dosa"]`, `user.name`, JSON।
- **गिनती:** किसी किताब में हर शब्द कितनी बार आया, हर product कितनी बार बिका, हर IP address
  ने कितनी बार connect किया। Key वो चीज़ है, value उसकी गिनती।
- **Caches:** किसी महँगे सवाल का जवाब (एक web page, database की एक row) उसकी key के नीचे रख
  लीजिए, और अगली बार तुरंत लौटा दीजिए।
- **Sets:** ऐसा hash map जो सिर्फ़ keys रखता है, "क्या मैंने इसे पहले देखा है?" का जवाब `O(1)`
  में देता है। इसी तरह duplicates हटाए जाते हैं और किसी search में देखी हुई जगहें याद रखी जाती हैं।
- Databases और search engines में **indexes**, ताकि एक lookup को पूरी table न पढ़नी पड़े।
- **आपके phone के contacts**, DNS (नाम से address), compilers (variable के नाम से उसका type), और
  interview का classic सवाल "ऐसे दो numbers ढूँढिए जिनका जोड़ एक target के बराबर हो"।
