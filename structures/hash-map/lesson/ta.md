**Hash map** இணைகளை (pairs) வைத்திருக்கிறது: ஒரு **key**, அதற்குச் சொந்தமான **value**. ஒரு
வார்த்தையும் அதன் பொருளும் போல, அல்லது ஒரு உணவும் அதன் விலையும் போல. அதற்கு key-ஐக் கொடுங்கள்,
மற்ற எதையும் தேடாமல், ஒரே தாவலில் அது value-ஐ உங்கள் கையில் தருகிறது. Python-இன் `dict`,
Java-வின் `HashMap`, C++-இன் `unordered_map`, JavaScript-இன் `Map`, PHP-இன் associative arrays
ஆகியவற்றுக்குப் பின்னால் இருக்கும் structure இது தான். சில புத்தகங்கள் இதை **hash table** என்றோ
**dictionary** என்றோ அழைக்கின்றன.

இதன் சூட்சுமம் ஒரு **hash function**: எந்த key-ஐயும் ஒரு number-ஆக மாற்றும் ஒரு வேகமான கணக்கு,
அந்த number அந்த இணை சரியாக எங்கே வைக்கப்பட்டுள்ளது என்று சொல்கிறது.

## அன்றாட வாழ்க்கையில்

ஒரு தபால் நிலையத்தின் sorting rack-ஐ நினைத்துப் பாருங்கள்: `0`, `1`, `2`, `3` என்று எண்ணிடப்பட்ட
**அறைகள்** (pigeonholes) உள்ள ஒரு மரப் பலகை. வரும் ஒவ்வொரு கடிதமும் ஏதாவது ஒரு அறைக்குள் போக
வேண்டும், எந்த அறை என்று தேர்ந்தெடுக்க sorter ஒரு நிலையான விதியைப் பயன்படுத்துகிறார்: சொல்லப்போனால்,
கவரில் உள்ள பெயரின் எழுத்துக்களைக் கூட்டி, அறைகளின் எண்ணிக்கையால் வகுத்து மீதியை எடுப்பது. யோசனை
இல்லை, தேடல் இல்லை, ஒவ்வொரு முறையும் ஒரே பதில்.

"*tea*-க்கு ஏதாவது கடிதம் இருக்கிறதா?" என்று யாராவது கேட்டால், sorter அதே கூட்டலைச் செய்து, நேராக
அந்த ஒரு அறைக்குப் போய், அதில் உள்ள சில கவர்களை மட்டும் புரட்டிப் பார்க்கிறார். மற்ற பெயர்களுக்கான
கடிதங்கள் தொடப்படுவதே இல்லை. அது தான் ஒரு hash map:

- அந்த **விதி** தான் hash function.
- அந்த **அறைகள்** தான் **buckets**.
- இரண்டு பெயர்கள் ஒரே அறையில் விழுவது ஒரு **collision**. அந்தக் கவர்கள் அந்த அறையில் ஒன்றாகவே
  இருக்கும், ஒன்றைக் கண்டுபிடிக்க மற்றவற்றைப் புரட்டிக் கடக்க வேண்டும், அவ்வளவு தான்.
- அறைகள் நெரிசலாகும் போது, தபால் நிலையம் **பெரிய rack** ஒன்றை வாங்கி, புதிய அறை எண்ணிக்கையுடன்
  ஒவ்வொரு கடிதத்தையும் மீண்டும் sort செய்கிறது.

இதே idea-வை ஒரு அகராதியில் (முதல் எழுத்து உங்களைச் சரியான பகுதிக்கு அனுப்புகிறது), ஒரு நூலகத்தில்
(shelf number புத்தகத்தின் மேலேயே அச்சிடப்பட்டிருக்கும்), தேர்வு அறையில் (உங்கள் roll number உங்கள்
இருக்கையைச் சொல்கிறது) பார்க்கலாம்.

## இது எப்படி வேலை செய்கிறது

Hash map என்பது **buckets**-இன் ஒரு array. ஒவ்வொரு bucket-உம் entries-இன் ஒரு **chain**-ஐ, அதாவது
ஒரு சின்ன linked list-ஐ, வைத்திருக்கிறது; ஒவ்வொரு entry-உம் ஒரு key, அதன் value, chain-இல் அடுத்த
entry ஆகிய மூன்றையும் நினைவில் வைத்திருக்கிறது. Collisions-ஐக் கையாளும் இந்த முறைக்கு **chaining**
என்று பெயர்.

நம் hash function வேண்டுமென்றே எளிமையானது: key-இன் character codes-ஐக் கூட்டுவது. `t`-இன் code
`116`, `e`-இன் code `101`, `a`-இன் code `97`, அதனால் `tea`-இன் hash `314`. அதை buckets-இன்
எண்ணிக்கையால் வகுத்து மீதியை வைத்துக்கொண்டால் bucket கிடைக்கிறது: `4` buckets இருந்தால்,
`314 % 4 = 2`, அதனால் `tea` bucket `2`-இல் இருக்கிறது. எவ்வளவு நீளமான key-உம் ஒரு சின்ன index-ஆக
மாறுகிறது.

`idli`-இன் hash `418`, `418 % 4`-உம் `2` தான். அது ஒரு collision: `idli`-உம் `tea`-உம் bucket `2`-ஐப்
பகிர்ந்துகொள்கின்றன, ஒன்றன் பின் ஒன்றாக chain-இல். Collisions சாதாரணமானவை. ஒரு hash map
chains-ஐச் சிறியதாக வைத்திருந்தால் போதும்.

`count`, அதாவது வைக்கப்பட்டுள்ள keys-இன் எண்ணிக்கை, மற்றும் `bucketCount`, அதாவது buckets-இன்
எண்ணிக்கை, இரண்டையும் வைத்துக்கொள்கிறோம். அவற்றின் விகிதம், `count / bucketCount`, தான் **load
factor**: table எவ்வளவு நெரிசலாக உள்ளது என்பது.

> **நாமே ஏன் உருவாக்க வேண்டும்?** ஒவ்வொரு மொழியிலும் ஒன்று உள்ளது: Python-இல் `dict`, C++-இல்
> `std::unordered_map`, Java-வில் `HashMap`, JavaScript-இல் `Map` (ஒவ்வொரு சாதாரண object-உம் கூட),
> PHP-இல் string keys உள்ள arrays. நீங்கள் அவற்றைத் தான் பயன்படுத்துவீர்கள். ஆனால் ஒருமுறை
> நீங்களே ஒன்றை உருவாக்கினால், `get` ஏன் வேகமானது, ஒரு collision என்ன விலை வாங்குகிறது, ஒரு
> மோசமான hash function ஏன் அதை ஊர்ந்து போக வைக்கும் என்பது உங்களுக்குத் தெரிந்திருக்கும்.
> Interview-களில் சரியாக இதைத் தான் கேட்பார்கள்.

## Operations

Hash map-க்கு மூன்று முக்கிய operations உள்ளன, ஒவ்வொன்றும் ஒரே மாதிரியாகத் தான் தொடங்குகிறது:
key-ஐ hash செய்யுங்கள், bucket-ஐக் கண்டுபிடியுங்கள். அந்த bucket-இன் chain மட்டுமே எப்போதும்
பார்க்கப்படுகிறது.

### put: ஒரு key-ஐ அதன் value-உடன் வைப்பது

1. Key-ஐ hash செய்து அதன் bucket-க்குப் போங்கள்.
2. Chain-இல் நடங்கள். Key ஏற்கனவே அங்கே இருந்தால், அதன் value-ஐ மாற்றிவிட்டு நிறுத்துங்கள். ஒரு
   hash map-இல் ஒரு key ஒரே ஒரு முறை தான் இருக்கும்.
3. ஒவ்வொரு bucket-இலும் சராசரியாக ஏற்கனவே ஒரு key இருந்தால் (`count`-உம் `bucketCount`-உம்
   சமம்), table நெரிசலாகிக்கொண்டிருக்கிறது: முதலில் அதை **grow** செய்யுங்கள் (கீழே பாருங்கள்).
4. ஒரு புதிய entry உருவாக்கி chain-இன் **முன்பக்கத்தில்**, அங்கே ஏற்கனவே இருந்ததற்கு முன்னால்,
   வையுங்கள். `count`-உடன் ஒன்றைக் கூட்டுங்கள்.

<!-- code: put -->

Demo-வில், `put dosa=40` காலியான bucket `3`-க்குள் போகிறது. `put idli=30` bucket `2`-இல் ஏற்கனவே
`tea`-ஐப் பார்க்கிறது, அதனால் chain `idli=30 -> tea=10` ஆகிறது. `put tea=12` அந்த chain-இல்
`tea`-ஐக் கண்டுபிடித்து அதன் value-ஐ மட்டும் மாற்றுகிறது.

### get: ஒரு key-க்கான value-ஐக் கண்டுபிடிப்பது

1. Key-ஐ hash செய்து அதன் bucket-க்குப் போங்கள்.
2. Keys-ஐ ஒப்பிட்டுக்கொண்டே chain-இல் நடங்கள். Key பொருந்தியவுடன் value-ஐ return செய்யுங்கள்.
3. பொருத்தம் இல்லாமல் chain முடிந்துவிட்டால், அந்த key map-இல் இல்லவே இல்லை. வேறு எந்த bucket-உம்
   அதை வைத்திருக்க முடியாது, அதனால் மேலும் தேட எதுவும் இல்லை.

<!-- code: get -->

`get idli` நேராக bucket `2`-க்குப் போய் முன்பக்கத்திலேயே `idli`-ஐக் கண்டுபிடிக்கிறது: ஒரே ஒரு
comparison. `get puri`-இன் hash `448`, `448 % 4 = 0`, bucket `0`-இல் `vada` மட்டுமே உள்ளது,
அதனால் ஒரு comparison-க்குப் பிறகே `puri` இங்கே இல்லை என்று நமக்குத் தெரிந்துவிடுகிறது.

### remove: ஒரு key-ஐ வெளியே எடுப்பது

1. Key-ஐ hash செய்து அதன் bucket-க்குப் போங்கள்.
2. **முந்தைய** entry-ஐ நினைவில் வைத்துக்கொண்டே chain-இல் நடங்கள்.
3. Key பொருந்தியதும், அந்த entry-ஐ unlink செய்யுங்கள்: முந்தைய entry-ஐ (அல்லது அது chain-இல்
   முதலாவதாக இருந்தால் bucket-ஐயே) அதற்கு அடுத்ததை நோக்கிக் காட்ட வையுங்கள். `count`-இலிருந்து
   ஒன்றைக் கழியுங்கள்.

### Table-ஐ வளர்ப்பது

`count` `bucketCount`-ஐ எட்டும் போது, chains நீளமாகப் போகின்றன, அதனால் table தன் buckets-இன்
எண்ணிக்கையை இரட்டிப்பாக்குகிறது. இரட்டிப்பாக்குவது hash கணக்கில் உள்ள `%`-ஐ மாற்றுகிறது, அதனால்
ஒவ்வொரு key-ஐயும் மீண்டும் வைக்க வேண்டும்: `vada`-இன் hash `412`, அது `4`-இல் bucket `0`-ஆக
இருந்தது, ஆனால் `8`-இல் bucket `4`. இதற்கு **rehashing** என்று பெயர்.

Entries நகர்த்தப்படும் போது ஒரு bucket-க்குள் அவற்றின் வரிசை முறை மாறலாம். அது பரவாயில்லை: ஒரு
hash map எந்த வரிசை முறையையும் ஒருபோதும் வாக்குறுதி தரவில்லை.

## இது எவ்வளவு வேகமானது?

ஒரு நல்ல hash function-உடனும், தேவைப்படும் போது வளரும் ஒரு table-உடனும், ஒவ்வொரு chain-இலும் சுமார்
ஒரு entry தான் இருக்கும். அதனால் `put`, `get`, `remove` ஒவ்வொன்றும் ஒரு hash கணக்கு, ஒரு array
lookup, ஓரிரு comparisons மட்டுமே செய்கின்றன: எத்தனை keys வைக்கப்பட்டிருந்தாலும் `O(1)`. நூறு
keys-ஆனாலும் பத்து கோடி keys-ஆனாலும், ஒரே வேகம். அதனால் தான் hash maps எல்லா இடத்திலும் உள்ளன.

| Operation | இது என்ன செய்கிறது | Time |
|---|---|---|
| `put` | hash செய்து, bucket-க்குப் போய், ஒரு சின்ன chain-இல் நடப்பது | சராசரியாக `O(1)` |
| `get` | hash செய்து, bucket-க்குப் போய், ஒரு சின்ன chain-இல் நடப்பது | சராசரியாக `O(1)` |
| `remove` | hash செய்து, bucket-க்குப் போய், ஒரு entry-ஐ unlink செய்வது | சராசரியாக `O(1)` |
| `grow` | ஒவ்வொரு key-ஐயும் மீண்டும் வைப்பது | `O(n)`, ஆனால் அரிது |
| `keys` | ஒவ்வொரு bucket-ஐயும் ஒவ்வொரு chain-ஐயும் பார்ப்பது | `O(n)` |

அந்த table-இல் இரண்டு எச்சரிக்கைகள் ஒளிந்திருக்கின்றன. முதலாவது, "சராசரியாக": hash function
ஒவ்வொரு key-ஐயும் ஒரே bucket-க்கு அனுப்பினால், map ஒரே ஒரு நீளமான chain ஆகிவிடும், எல்லாமே
`O(n)` ஆகிவிடும். இரண்டாவது, வளரும் போது `O(n)` செலவாகிறது, ஆனால் keys-இன் எண்ணிக்கை
இரட்டிப்பான பிறகே அது நடக்கிறது, அதனால் எல்லா puts-இலும் பரவலாகப் பிரித்தால் ஒரு `put`-க்கான செலவு
இன்னும் constant தான்.

`n` keys உள்ள ஒரு hash map entries-க்கு `O(n)` memory-உம், கூடவே buckets-இன் ஒரு array-உம்
பயன்படுத்துகிறது.

## பொதுவான தவறுகள்

- **ஒரு வரிசை முறையை எதிர்பார்ப்பது.** Demo-வில் `keys` `coffee, tea, vada, dosa` என்று return
  செய்கிறது: bucket வரிசை முறையில், சேர்க்கப்பட்ட வரிசை முறையில் அல்ல, table வளரும் போது அது மாறவும்
  செய்கிறது. வரிசை முறை வேண்டுமா? Map-இன் பக்கத்தில் ஒரு list வைத்துக்கொள்ளுங்கள், அல்லது ஒரு
  sorted structure பயன்படுத்துங்கள்.
- **பலவீனமான hash function.** நம் எழுத்துக் கூட்டல் ஒவ்வொரு anagram-ஐயும் ஒரே bucket-க்கு
  அனுப்புகிறது: `listen`, `silent`, `enlist` எல்லாவற்றின் hash-உம் `655`. உண்மையான hash functions
  characters-ஐக் கலக்கின்றன, எடுத்துக்காட்டாக ஒவ்வொரு character-க்கும் `hash = hash * 31 + code`,
  அப்போது எழுத்துக்களின் வரிசை முறையும் முக்கியமாகிறது.
- **ஒருபோதும் வளர்க்காமல் இருப்பது.** `grow` இல்லாமல், ஒவ்வொரு key-உடனும் chains நீளமாகின்றன, `get`
  அமைதியாக `O(1)`-இலிருந்து `O(n)`-ஐ நோக்கி நழுவுகிறது.
- **`put` ஒரு update-ஆகவும் இருக்கலாம் என்பதை மறப்பது.** ஒரு key ஒரே ஒரு முறை தான் இருக்கும். `put`
  முதலில் ஏற்கனவே உள்ள key-ஐச் சரிபார்க்கவில்லை என்றால், map-இல் `tea`-க்கு இரண்டு entries வந்துவிடும்,
  `get` எது முதலில் வருகிறதோ அதை return செய்யும்.
- **வைத்த பிறகு ஒரு key-ஐ மாற்றுவது.** Bucket key-இன் பழைய value-இலிருந்து தேர்ந்தெடுக்கப்பட்டது,
  அதனால் அந்த entry-ஐ இனி கண்டுபிடிக்கவே முடியாது. ஒருபோதும் மாறாத keys பயன்படுத்துங்கள்:
  strings-உம் numbers-உம், lists அல்ல.
- **"கிடைக்கவில்லை" என்பதையும் வைக்கப்பட்ட ஒன்றுமில்லாததையும் குழப்புவது.** Key இல்லாத போது `get`
  `None`, `null` அல்லது `undefined` return செய்கிறது. அப்படிப்பட்ட ஒரு value-ஐயும் நீங்கள் வைத்தால்,
  இரண்டையும் பிரித்தறிய முடியாது; ஒரு key இருக்கிறதா என்று கேட்க `contains` பயன்படுத்துங்கள்.

## இது எங்கே பயன்படுகிறது?

- ஒவ்வொரு மொழியிலும் **dictionaries-உம் objects-உம்**: `prices["dosa"]`, `user.name`, JSON.
- **எண்ணுவது:** ஒரு புத்தகத்தில் ஒவ்வொரு வார்த்தையும் எத்தனை முறை வருகிறது, ஒவ்வொரு product-உம்
  எத்தனை விற்கிறது, ஒவ்வொரு IP address-உம் எத்தனை முறை connect ஆகிறது. பொருள் தான் key, அதன்
  எண்ணிக்கை தான் value.
- **Caches:** ஒரு விலையுயர்ந்த கேள்விக்கான பதிலை (ஒரு web page, ஒரு database row) அதன் key-இன் கீழ்
  வைத்து, அடுத்த முறை உடனே return செய்வது.
- **Sets:** keys-ஐ மட்டும் வைத்துக்கொள்ளும் ஒரு hash map, "இதை நான் முன்பே பார்த்திருக்கிறேனா?"
  என்பதற்கு `O(1)`-இல் பதில் சொல்கிறது. Duplicates நீக்கப்படுவதும், ஒரு search-இல் போன இடங்கள்
  நினைவில் வைக்கப்படுவதும் இப்படித் தான்.
- Databases-இலும் search engines-இலும் **indexes**, அதனால் ஒரு lookup முழு table-ஐயும் படிக்கத்
  தேவையில்லை.
- **உங்கள் phone-இன் contacts**, DNS (பெயரிலிருந்து address), compilers (variable பெயரிலிருந்து அதன்
  type), பிரபலமான interview கேள்வியான "ஒரு target-க்குக் கூட்டுத்தொகையாகும் இரண்டு numbers-ஐக்
  கண்டுபிடியுங்கள்".
