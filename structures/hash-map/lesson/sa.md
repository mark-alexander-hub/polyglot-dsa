**Hash map** इति युग्मानि स्थापयति: एकः **key**, तथा तस्य **value**, यथा शब्दः तस्य अर्थः च,
अथवा भोज्यं तस्य मूल्यं च। तस्मै key दत्त, तत् एकेन एव उत्प्लवनेन value ददाति, अन्यत् किमपि
न पश्यति। एषा एव रचना Python इत्यस्य `dict`, Java इत्यस्य `HashMap`, C++ इत्यस्य
`unordered_map`, JavaScript इत्यस्य `Map`, तथा PHP इत्यस्य associative arrays इत्येतेषाम् अन्तः
अस्ति। कानिचित् पुस्तकानि एतत् **hash table** अथवा **dictionary** इति वदन्ति।

रहस्यम् एकः **hash function**: शीघ्रा गणना, या कमपि key सङ्ख्यारूपं नयति। सा सङ्ख्या एव
निश्चयेन वदति, युग्मं कुत्र स्थापितम् इति।

## वास्तविकजीवने

डाकघरस्य (post office) पत्रविभाजनफलकं चिन्तयत: काष्ठफलकं **कोष्ठैः** युक्तम्, येषां सङ्ख्याः
`0`, `1`, `2`, `3`। आगतं प्रत्येकं पत्रम् एकस्मिन् कोष्ठे स्थापनीयम्, तं कोष्ठं च विभाजकः एकेन
निश्चितेन नियमेन चिनोति: यथा, पत्रे लिखितस्य नाम्नः अक्षराणि योजयत, ततः कोष्ठसङ्ख्यया विभज्य
शेषं गृह्णीत। न चिन्तनम्, न अन्वेषणम्, प्रतिवारं तदेव उत्तरम्।

यदा कश्चित् पृच्छति "*tea* इत्यस्य कृते किं पत्रम् अस्ति?", तदा विभाजकः ताम् एव गणनां करोति,
साक्षात् तम् एकं कोष्ठं गच्छति, तत्र स्थितानि कतिपयानि पत्राणि च पश्यति। अन्येषां नाम्नां
पत्राणि कदापि न स्पृश्यन्ते। एषः एव hash map:

- **नियमः** एव hash function।
- **कोष्ठाः** एव **buckets**।
- द्वे नाम्नी एकस्मिन् एव कोष्ठे पततः चेत्, सः **collision**। पत्राणि तस्मिन् कोष्ठे सह एव
  तिष्ठन्ति, एकस्य प्राप्तिः च अन्यानि अतिक्रम्य दर्शनम्।
- यदा कोष्ठाः संकीर्णाः भवन्ति, तदा डाकघरं **महत्तरं फलकं** गृह्णाति, नूतनया कोष्ठसङ्ख्यया च
  सर्वाणि पत्राणि पुनः विभजति।

एषा एव कल्पना शब्दकोशे (प्रथमम् अक्षरं युष्मान् उचितं भागं नयति), पुस्तकालये (पुस्तके एव तस्य
shelf इत्यस्य सङ्ख्या लिखिता), परीक्षाभवने च दृश्यते, यत्र युष्माकं roll number युष्माकम्
आसनं वदति।

## एतत् कथं कार्यं करोति

hash map इति **buckets** इत्येतेषाम् एकम् array। प्रत्येकः bucket entries इत्येतेषाम् एकं
**chain** धारयति, अर्थात् एकं लघु linked list; प्रत्येकं entry च एकं key, तस्य value, chain
इत्यस्मिन् अग्रिमम् entry च स्मरति। collision इत्यस्य एषः उपायः **chaining** इति उच्यते।

अस्माकं hash function जानद्भिः एव सरलः कृतः: key इत्यस्य अक्षराणां codes योजयत। `t` इत्यस्य
code `116`, `e` इत्यस्य `101`, `a` इत्यस्य `97`, अतः `tea` इत्यस्य hash `314`। buckets इत्येतेषां
सङ्ख्यया विभज्य शेषं गृहीत्वा bucket लभ्यते: `4` buckets सत्सु `314 % 4 = 2`, अतः `tea` bucket
`2` इत्यस्मिन् वसति। कोऽपि key, यावान् दीर्घः स्यात्, एकः लघुः index भवति।

`idli` इत्यस्य hash `418`, `418 % 4` अपि `2` एव। एषः collision: `idli` तथा `tea` bucket `2` इति
समानं bucket धारयतः, एकस्य पश्चात् अन्यत् chain रूपेण। collisions सामान्याः एव। hash map
इत्यस्य कार्यं केवलम् एतत्, यत् chains लघूनि तिष्ठेयुः।

वयं `count` (स्थापितानां keys इत्येतेषां सङ्ख्या) तथा `bucketCount` (buckets इत्येतेषां सङ्ख्या)
च रक्षामः। तयोः अनुपातः `count / bucketCount` इति **load factor**: table कियत् संकीर्णम् इति।

## Operations

hash map इत्यस्य त्रीणि मुख्यानि operations सन्ति, प्रत्येकं च समानेन एव प्रकारेण आरभते: key
इत्यस्य hash गणयत, bucket प्राप्नुत। केवलं तस्य एव bucket इत्यस्य chain दृश्यते।

### put: एकं key तस्य value इत्यनेन सह स्थापनम्

1. key इत्यस्य hash गणयत, तस्य bucket गच्छत।
2. chain इत्यस्मिन् गच्छत। यदि सः key तत्र पूर्वम् एव अस्ति, तर्हि तस्य value परिवर्तयत, विरमत
   च। hash map इत्यस्मिन् एकः key एकवारम् एव भवति।
3. यदि प्रत्येकस्मिन् bucket इत्यस्मिन् पूर्वम् एव सामान्यतः एकः key अस्ति (`count` इति
   `bucketCount` इत्यस्य समम्), तर्हि table संकीर्णं भवति: प्रथमं तत् **वर्धयत** (अधः पश्यत)।
4. नूतनम् entry रचयत, chain इत्यस्य **अग्रे** स्थापयत, यत् किमपि पूर्वम् आसीत् तस्य पुरतः।
   `count` इत्यस्मिन् एकं योजयत।

### get: एकस्य key इत्यस्य value इत्यस्य प्राप्तिः

1. key इत्यस्य hash गणयत, तस्य bucket गच्छत।
2. chain इत्यस्मिन् गच्छत, keys तुलयत। यदा key समानः, तदा एव value प्रत्यर्पयत।
3. यदि chain समाप्तं, key च न प्राप्तः, तर्हि सः key map इत्यस्मिन् नास्ति एव। अन्यः कोऽपि bucket
   तं धारयितुं न शक्नोति, अतः अन्वेष्टव्यम् अन्यत् किमपि नास्ति।

### remove: एकस्य key इत्यस्य अपनयनम्

1. key इत्यस्य hash गणयत, तस्य bucket गच्छत।
2. chain इत्यस्मिन् गच्छत, **पूर्वम्** entry च स्मरत।
3. यदा key समानः, तदा तत् entry विमोचयत: पूर्वम् entry (अथवा bucket एव, यदि तत् प्रथमम् आसीत्)
   तस्य अग्रिमम् entry प्रति निर्दिशत। `count` इत्यतः एकं न्यूनं कुरुत।

## एतत् कियत् शीघ्रम्?

उचितेन hash function इत्यनेन, यथासमयं वर्धमानेन table इत्यनेन च, प्रत्येकं chain प्रायः एकम्
एव entry धारयति। अतः `put`, `get`, `remove` इत्येतानि एकां hash गणनाम्, एकम् array इत्यस्मिन्
दर्शनम्, एकां द्वे वा तुलने च कुर्वन्ति: `O(1)`, यावन्तः keys स्थापिताः स्युः। शतं keys अथवा
दशकोटिः, समानः एव वेगः। अत एव hash maps सर्वत्र सन्ति।

| Operation | एतत् किं करोति | Time |
|---|---|---|
| `put` | hash गणयति, bucket गच्छति, लघु chain पश्यति | सामान्यतः `O(1)` |
| `get` | hash गणयति, bucket गच्छति, लघु chain पश्यति | सामान्यतः `O(1)` |
| `remove` | hash गणयति, bucket गच्छति, एकम् entry विमोचयति | सामान्यतः `O(1)` |
| `grow` | प्रत्येकं key पुनः स्थापयति | `O(n)`, किन्तु विरलम् |
| `keys` | प्रत्येकं bucket, प्रत्येकं chain च पश्यति | `O(n)` |

तस्मिन् table इत्यस्मिन् द्वे सूचने निगूढे। प्रथमं, "सामान्यतः": यदि hash function प्रत्येकं
key समानं bucket प्रेषयति, तर्हि map एकं दीर्घं chain भवति, सर्वं च `O(n)` भवति। द्वितीयं,
वर्धनस्य व्ययः `O(n)`, किन्तु तत् केवलं तदा भवति यदा keys इत्येतेषां सङ्ख्या द्विगुणा भवति,
अतः सर्वेषु puts इत्येतेषु विभक्तः प्रत्येकस्य `put` इत्यस्य व्ययः अद्यापि स्थिरः एव।

`n` keys युक्तः hash map entries इत्येतेषां कृते `O(n)` memory, तथा buckets इत्येतेषाम् एकम्
array च उपयुङ्क्ते।

## सामान्याः त्रुटयः

- **क्रमस्य आशा।** demo इत्यस्मिन् `keys` इति `coffee, tea, vada, dosa` इति प्रत्यर्पयति: bucket
  इत्यस्य क्रमः, न तु योजनक्रमः; table वर्धमाने सः परिवर्तते च। क्रमः आवश्यकः? map इत्यस्य
  पार्श्वे एकां list रक्षत, अथवा sorted रचनाम् उपयुङ्ध्वम्।
- **दुर्बलः hash function।** अस्माकम् अक्षरयोगः प्रत्येकम् anagram समानं bucket प्रेषयति:
  `listen`, `silent`, `enlist` इत्येतेषां सर्वेषां hash `655`। वास्तविकाः hash functions अक्षराणि
  मिश्रयन्ति, यथा प्रत्येकस्य अक्षरस्य कृते `hash = hash * 31 + code`, येन अक्षराणां क्रमः अपि
  गण्यते।
- **कदापि न वर्धनम्।** `grow` विना प्रत्येकेन key इत्यनेन chains दीर्घाणि भवन्ति, `get` च शनैः
  `O(1)` इत्यतः `O(n)` प्रति सर्पति।
- **`put` इति परिवर्तनम् अपि स्यात् इति विस्मरणम्।** एकः key एकवारम् एव भवति। यदि `put` प्रथमं
  विद्यमानं key न परीक्षते, तर्हि map इत्यस्मिन् `tea` इत्यस्य द्वे entries भवतः, `get` च यत्
  प्रथमम् आगच्छति तत् प्रत्यर्पयति।
- **स्थापनात् परं key इत्यस्य परिवर्तनम्।** bucket इति key इत्यस्य पुरातनात् रूपात् चितः, अतः तत्
  entry पुनः न प्राप्यते। ये कदापि न परिवर्तन्ते, तान् एव keys उपयुङ्ध्वम्: strings तथा सङ्ख्याः,
  न तु lists।
- **"न प्राप्तम्" इति तथा स्थापितं शून्यं च इति मिश्रणम्।** key नास्ति चेत् `get` इति `None`,
  `null` अथवा `undefined` प्रत्यर्पयति। यदि यूयम् एतादृशं value अपि स्थापयथ, तर्हि द्वयोः भेदं
  ज्ञातुं न शक्नुथ; key अस्ति वा इति प्रष्टुं `contains` उपयुङ्ध्वम्।

## एतत् कुत्र प्रयुज्यते?

- **Dictionaries तथा objects** प्रत्येकस्यां भाषायाम्: `prices["dosa"]`, `user.name`, JSON।
- **गणनम्:** पुस्तके प्रत्येकः शब्दः कतिवारम् आगच्छति, प्रत्येकं वस्तु कतिवारं विक्रीयते,
  प्रत्येकं IP address कतिवारं सम्बध्यते। key इति वस्तु, value इति तस्य गणना।
- **Caches:** व्ययबहुलस्य प्रश्नस्य उत्तरं (web page, database इत्यस्य row) तस्य key इत्यस्य अधः
  रक्षत, अग्रिमवारं च तत्क्षणम् एव प्रत्यर्पयत।
- **Sets:** केवलं keys रक्षन् hash map "एतत् मया पूर्वं दृष्टं वा?" इति `O(1)` समये उत्तरं ददाति।
  एवम् एव duplicates अपनीयन्ते, अन्वेषणे च गतानि स्थानानि स्मर्यन्ते।
- databases इत्येतेषु search engines इत्येतेषु च **indexes**, येन एकम् अन्वेषणं सम्पूर्णं table
  न पठति।
- **युष्माकं phone इत्यस्य contacts**, DNS (नाम्नः address प्रति), compilers (variable इत्यस्य
  नाम्नः तस्य type प्रति), तथा प्रसिद्धः interview प्रश्नः "ये द्वे सङ्ख्ये योजिते लक्ष्यं भवतः,
  ते प्राप्नुत"।
