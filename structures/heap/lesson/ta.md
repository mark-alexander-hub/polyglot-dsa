**Heap** என்பது மிகச் சிறிய value-ஐ எப்போதும் மேலே வைத்திருக்கும் ஒரு மரம் (tree). அதில் உள்ள
ஒவ்வொரு value-உம் தனக்குக் கீழே தொங்கும் இரண்டு values-ஐ விடச் சிறியது (அல்லது சமம்), அதனால்
மேலே இருப்பது, அதற்கு **root** என்று பெயர், முழு heap-இலும் மிகச் சிறிய value. இந்த வகைக்கு
**min-heap** என்று பெயர். விதியைத் தலைகீழாக்கினால் மிகப் பெரிய value மேலே இருக்கும்: அது
**max-heap**.

**Priority queue** உருவாக்க heap தான் வழக்கமான வழி: எந்த வரிசை முறையில் உள்ளே போனாலும், மிக
அவசரமானது முதலில் வெளியே வரும் ஒரு queue.

## அன்றாட வாழ்க்கையில்

ஒரு மருத்துவமனையின் அவசர சிகிச்சைப் பிரிவை (emergency ward) நினைத்துப் பாருங்கள். நோயாளிகள்
உள்ளே வந்த வரிசை முறையில் சிகிச்சை பெறுவதில்லை. ஒவ்வொருவருக்கும் எவ்வளவு அவசரம் என்பதற்கு nurse
ஒரு number கொடுக்கிறார், மிக மோசமான நிலைக்கு `1`, doctor எப்போதும் மிகச் சிறிய number உள்ள
நோயாளியை அடுத்து அழைக்கிறார். புதிய நோயாளிகள் புதிய numbers-உடன் வந்துகொண்டே இருக்கிறார்கள்,
"அடுத்து யார்?" என்பதற்கு உடனே பதில் கிடைக்க வேண்டும்.

Heap செய்வது சரியாக இதைத் தான்:

- புதிய நோயாளியை சில steps-இல் **insert** செய்வது.
- மிக அவசரமானவரை உடனே **peek** செய்வது.
- மிக அவசரமானவரை **remove** செய்வது, அடுத்த அவசரமானவர் மேலே வருவார்.

இதே idea-வை **விமான நிலைய boarding queue**-இல் (priority groups முதலில்), உங்கள் மிக அவசரமான
வேலையை எப்போதும் மேலே காட்டும் **to-do list**-இல், உங்கள் computer-க்கு உள்ளேயும், அங்கே operating
system அடுத்து இயக்க மிக அவசரமான job-ஐத் தேர்ந்தெடுக்கிறது, பார்க்கலாம்.

## இது எப்படி வேலை செய்கிறது

Heap-ஐ மரமாக வரைகிறோம், ஆனால் ஒரு சாதாரண array-இல், level level-ஆக, வைக்கிறோம்: முதலில் root,
பிறகு அதன் இரண்டு children, பிறகு அவற்றின் நான்கு children, இப்படியே. Pointers எதுவும்
தேவையில்லை. ஒரு சின்னக் கணக்கு எந்த value-இன் குடும்பத்தையும் கண்டுபிடிக்கும்:

- Index `i`-இல் உள்ள value-இன் **parent** `(i - 1) / 2`-இல் உள்ளது (முழு எண் வகுத்தல்).
- அதன் **left child** `2 * i + 1`-இல், **right child** `2 * i + 2`-இல்.

அதனால் `[5, 17, 13, 42, 25, 30, 60]` என்ற array இந்த மரம்: `5` மேலே, அதன் கீழே `17`-உம் `13`-உம்,
பிறகு `17`-இன் கீழே `42`-உம் `25`-உம், `13`-இன் கீழே `30`-உம் `60`-உம். எந்த parent-ஐயும் அதன்
children-ஐயும் பாருங்கள்: parent தான் எப்போதும் சிறியது. இது தான் **heap விதி**.

மரம் எப்போதும் மேலிருந்து கீழாகவும் இடமிருந்து வலமாகவும், இடைவெளி இல்லாமல், நிரப்பப்படுகிறது.
இப்படிப்பட்ட மரத்துக்கு **complete** என்று பெயர். இது தான் அதை ஒரு array-இல் அடைக்க
அனுமதிக்கிறது: அடுத்த காலி index எப்போதும் மரத்தின் அடுத்த காலி இடம்.

`count`, அதாவது heap-இல் உள்ள values-இன் எண்ணிக்கை, மற்றும் ஒரு நிலையான **capacity**
வைத்துக்கொள்கிறோம்.

> **நாமே ஏன் உருவாக்க வேண்டும்?** ஒவ்வொரு மொழியிலும் heap அல்லது priority queue உள்ளது: Python-இல்
> `heapq`, C++-இல் `std::priority_queue`, Java-வில் `PriorityQueue`, PHP-இல் `SplMinHeap`.
> JavaScript-இல் built-in எதுவும் இல்லை, அதனால் சரியாக இந்த class-ஐத் தான் எழுதுவார்கள். ஒருமுறை
> நீங்களே உருவாக்கினால் அந்த tools ஏன் வேகமானவை என்று புரியும், interview-களிலும் இந்தக் கேள்வியை
> அடிக்கடி கேட்பார்கள்.

## Operations

Heap-க்கு மூன்று முக்கிய operations உள்ளன. `peek` மிக எளிது. `insert`-உம் `removeMin`-உம்
மரத்தில் ஒரு சின்ன நடை மேலேயோ கீழேயோ போய் heap விதியைச் சரி செய்கின்றன.

### insert: ஒரு value சேர்ப்பது

1. `count`-உம் `capacity`-உம் சமமாக இருந்தால், heap நிரம்பியது. Error கொடுத்து நிறுத்துங்கள்.
2. புதிய value-ஐ முதல் காலி இடத்தில், index `count`-இல், வைத்து, `count`-உடன் ஒன்றைக் கூட்டுங்கள்.
   இப்போது அது மிகப் புதிய leaf, கீழே வலது பக்கத்தில்.
3. **Sift up:** value தன் parent-ஐ விடச் சிறியதாக இருக்கும் வரை, இரண்டையும் swap செய்யுங்கள்.
   ஒவ்வொரு swap-உம் value-ஐ ஒரு level மேலே ஏற்றுகிறது. அதன் parent சிறியதாக இருந்தால், அல்லது
   அது root-ஐ அடைந்தால், நிறுத்துங்கள்.

`[17, 42, 30]`-இல் `8`-ஐ insert செய்யுங்கள்: அது index `3`-இல், `42`-க்குக் கீழே, விழுகிறது. அது
`42`-ஐ விடச் சிறியது, அதனால் இரண்டும் swap ஆகின்றன. இப்போது அது `17`-க்குக் கீழே, இன்னும் சிறியது,
அதனால் மீண்டும் swap ஆகின்றன. விடை: `[8, 17, 30, 42]`, இரண்டு swaps. Demo output-இல் ஒவ்வொரு
`insert` வரியும் எத்தனை swaps ஆனது என்று காட்டுகிறது.

### removeMin: மிகச் சிறிய value-ஐ எடுப்பது

1. `count`-இன் value `0` என்றால், heap காலியாக உள்ளது. Error கொடுத்து நிறுத்துங்கள்.
2. Root-ஐ நினைவில் வைத்துக்கொள்ளுங்கள்: அது தான் மிகச் சிறிய value, நாம் return செய்யப் போவது.
3. **கடைசி** value-ஐ root-இன் இடத்துக்கு நகர்த்தி, `count`-இலிருந்து ஒன்றைக் கழியுங்கள். மரம்
   இன்னும் complete தான், ஆனால் புதிய root பெரும்பாலும் ரொம்பப் பெரியது.
4. **Sift down:** value-ஐ அதன் இரண்டு children-உடன் ஒப்பிடுங்கள். ஏதாவது ஒரு child சிறியதாக
   இருந்தால், **சிறிய** child-உடன் swap செய்து அங்கிருந்து தொடருங்கள். இரண்டு children-உம்
   பெரியதாக இருந்தால், அல்லது children எதுவும் இல்லையென்றால், நிறுத்துங்கள்.

ஏன் சிறிய child? ஏனென்றால் swap-க்குப் பிறகு அந்த child தான் மற்றொன்றுக்கு parent ஆகிறது, parent
இரண்டு children-ஐ விடவும் சிறியதாக இருக்க வேண்டும்.

### peek: மிகச் சிறிய value-ஐப் பார்ப்பது

மிகச் சிறிய value எப்போதும் root தான், index `0`-இல். `peek` அதை return செய்கிறது, எதையும்
மாற்றுவதில்லை.

## இது எவ்வளவு வேகமானது?

`n` values உள்ள ஒரு complete மரத்துக்கு சுமார் `log₂ n` levels மட்டுமே உள்ளன: `7` values-க்கு `3`
levels, `1,000` values-க்கு `10`, பத்து லட்சத்துக்கு `20`. Sift up அல்லது sift down ஒரு level-க்கு
அதிகபட்சம் ஒரு value-ஐ மட்டுமே பார்க்கிறது, அதனால் `insert`-உம் `removeMin`-உம் `O(log n)` நேரம்
எடுக்கின்றன. ஒவ்வொரு முறையும் ஒரு சாதாரண list-ஐ முழுவதும் தேடி மிகச் சிறியதைக் கண்டுபிடிப்பதோடு
(`O(n)`) ஒப்பிட்டால், heap பெரிதானதும் இது மிகப் பெரிய சேமிப்பு.

| Operation | இது என்ன செய்கிறது | Time |
|---|---|---|
| `insert` | value சேர்த்து அதை sift up செய்வது | `O(log n)` |
| `removeMin` | root-ஐ எடுத்து, கடைசி value-ஐ மேலே ஏற்றி, அதை sift down செய்வது | `O(log n)` |
| `peek` | root-ஐப் பார்ப்பது | `O(1)` |
| `isEmpty` | `count`-இன் value `0` தானா என்று பார்ப்பது | `O(1)` |
| வேறு ஏதாவது value-ஐத் தேடுவது | எல்லா values-ஐயும் பார்ப்பது | `O(n)` |

`n` values-க்கு இடம் உள்ள heap `n` இடங்கள் உள்ள ஒரே ஒரு array பயன்படுத்துகிறது, அதனால் அதற்கு `O(n)`
memory தேவை.

## பொதுவான தவறுகள்

- **Array sorted-ஆக இருக்கும் என்று எதிர்பார்ப்பது.** `17 > 13` என்றாலும் `[5, 17, 13, 42, 25, 30, 60]`
  ஒரு சரியான heap தான். Parents-உம் children-உம் மட்டுமே வரிசை முறையில் உள்ளன, பக்கத்தில் இருப்பவை
  அல்ல. Sorted-ஆக வேண்டுமென்றால் `removeMin` மூலம் values-ஐ ஒவ்வொன்றாக எடுங்கள்.
- **தவறான child-க்கு sift down செய்வது.** எப்போதும் *சிறிய* child-உடன் swap செய்யுங்கள். பெரிய
  child-உடன் swap செய்தால், மற்ற child-க்கு heap விதி உடைந்துவிடும்.
- **Child இல்லாமல் இருக்கலாம் என்பதை மறப்பது.** படிப்பதற்கு முன் `left < count`, `right < count`
  சரிபாருங்கள். Heap-இன் கடைசி சில values-க்கு ஒரு child தான் இருக்கும், அல்லது ஒன்றும் இருக்காது.
- **குடும்பக் கணக்கில் ஒன்று வித்தியாசம்.** Root index `0`-இல் இருந்தால், `i`-இன் children `2i + 1`,
  `2i + 2`. சில புத்தகங்கள் index `1`-இல் தொடங்குகின்றன, அங்கே அவை `2i`, `2i + 1`. ஒன்றைத்
  தேர்ந்தெடுத்து அதிலேயே இருங்கள்.
- **சரிபார்க்காமல் remove செய்வது.** `removeMin` அல்லது `peek`-க்கு முன் `isEmpty()` சரிபாருங்கள்
  (அல்லது error-ஐப் பிடியுங்கள்).

## இது எங்கே பயன்படுகிறது?

- **Priority queues** எல்லா இடத்திலும்: printer jobs, மருத்துவமனை triage software, உங்கள் operating
  system அடுத்து இயக்கும் tasks.
- **Heap sort:** எல்லா values-ஐயும் insert செய்து, பிறகு காலியாகும் வரை `removeMin` செய்யுங்கள்.
  Values sorted-ஆக, `O(n log n)` நேரத்தில், வெளியே வரும். Demo output சரியாக இப்படித் தான் முடிகிறது.
- **Shortest paths.** மிக வேகமான route-ஐக் கண்டுபிடிக்க map apps பயன்படுத்தும் Dijkstra's algorithm,
  இன்னும் போக வேண்டிய ஊர்களை ஒரு heap-இல் வைத்திருக்கிறது, அதனால் மிக அருகில் உள்ளதை உடனே எடுக்க
  முடியும்.
- **Top-k problems**, அதாவது லட்சக்கணக்கானவற்றில் "மிக அதிகம் play செய்யப்பட்ட 10 பாடல்கள்", size
  `k` உள்ள ஒரு சின்ன heap மூலம்.
- பல sorted lists-ஐ ஒன்றாக **merge** செய்வது, search engines-உம் databases-உம் செய்வது போல.
- **Timers, events:** அடுத்து அடிக்கப் போகும் alarm எப்போதும் மிக முந்தைய நேரம் உள்ளது தான்.
