**Heap** ಎಂದರೆ ಅತಿ ಚಿಕ್ಕ value ಅನ್ನು ಯಾವಾಗಲೂ ಮೇಲೆ ಇಟ್ಟುಕೊಳ್ಳುವ ಒಂದು ಮರ (tree). ಅದರಲ್ಲಿರುವ ಪ್ರತಿ
value ತನ್ನ ಕೆಳಗೆ ನೇತಾಡುವ ಎರಡು values ಗಿಂತ ಚಿಕ್ಕದು (ಅಥವಾ ಸಮ). ಆದ್ದರಿಂದ ಮೇಲಿನ ತುದಿ, ಅಂದರೆ **root**,
ಇಡೀ heap ನ ಅತಿ ಚಿಕ್ಕ value. ಈ ರೀತಿಯ heap ಅನ್ನು **min-heap** ಎನ್ನುತ್ತಾರೆ. ನಿಯಮವನ್ನು ತಿರುಗಿಸಿದರೆ ಅತಿ
ದೊಡ್ಡ value ಮೇಲೆ ಕೂರುತ್ತದೆ: ಅದು **max-heap**.

**Priority queue** ಕಟ್ಟಲು heap ಗಳೇ ಸಾಮಾನ್ಯ ದಾರಿ: ಇದು ವಿಷಯಗಳು ಯಾವ ಕ್ರಮದಲ್ಲಿ ಬಂದರೂ, ಅತಿ ತುರ್ತು
ವಿಷಯ ಮೊದಲು ಹೊರಬರುವ ಒಂದು queue.

## ನಿಜ ಜೀವನದಲ್ಲಿ

ಆಸ್ಪತ್ರೆಯ emergency ward ಬಗ್ಗೆ ಯೋಚಿಸಿ. ರೋಗಿಗಳಿಗೆ ಅವರು ಬಂದ ಕ್ರಮದಲ್ಲಿ ಚಿಕಿತ್ಸೆ ಸಿಗುವುದಿಲ್ಲ. Nurse
ಪ್ರತಿಯೊಬ್ಬರಿಗೂ ಅವರ ಸ್ಥಿತಿ ಎಷ್ಟು ತುರ್ತು ಎಂದು ಹೇಳುವ ಒಂದು number ಕೊಡುತ್ತಾರೆ, ಅತಿ ಗಂಭೀರ ಸ್ಥಿತಿಗೆ `1`,
ಮತ್ತು doctor ಯಾವಾಗಲೂ ಅತಿ ಚಿಕ್ಕ number ಇರುವ ರೋಗಿಯನ್ನೇ ಮುಂದೆ ಕರೆಯುತ್ತಾರೆ. ಹೊಸ ರೋಗಿಗಳು ಹೊಸ numbers
ಜೊತೆ ಬರುತ್ತಲೇ ಇರುತ್ತಾರೆ, ಮತ್ತು "ಮುಂದೆ ಯಾರು?" ಎಂಬ ಪ್ರಶ್ನೆಗೆ ತಕ್ಷಣ ಉತ್ತರ ಸಿಗಬೇಕು.

Heap ಮಾಡುವುದು ನಿಖರವಾಗಿ ಇದನ್ನೇ:

- ಹೊಸ ರೋಗಿಯನ್ನು ಕೆಲವೇ steps ನಲ್ಲಿ **insert** ಮಾಡುವುದು.
- ಅತಿ ತುರ್ತು ರೋಗಿಯನ್ನು ತಕ್ಷಣ **peek** ಮಾಡಿ ನೋಡುವುದು.
- ಅತಿ ತುರ್ತು ರೋಗಿಯನ್ನು **remove** ಮಾಡುವುದು, ಆಗ ಮುಂದಿನ ಅತಿ ತುರ್ತು ರೋಗಿ ಮೇಲೆ ಬರುತ್ತಾರೆ.

ಇದೇ idea ನಿಮಗೆ ಇನ್ನೂ ಹಲವು ಕಡೆ ಸಿಗುತ್ತದೆ: **airport boarding ಸಾಲಿನಲ್ಲಿ** (priority groups ಮೊದಲು),
ನಿಮ್ಮ ಅತಿ ತುರ್ತು ಕೆಲಸವನ್ನು ಯಾವಾಗಲೂ ಮೇಲೆ ತೋರಿಸುವ **to-do list** ನಲ್ಲಿ, ಮತ್ತು ನಿಮ್ಮ computer ನ ಒಳಗೂ,
ಅಲ್ಲಿ operating system ಮುಂದೆ ಚಲಾಯಿಸಲು ಅತಿ ತುರ್ತು job ಅನ್ನು ಆರಿಸುತ್ತದೆ.

## ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ನಾವು heap ಅನ್ನು ಮರದಂತೆ ಬಿಡಿಸುತ್ತೇವೆ, ಆದರೆ ಅದನ್ನು ಒಂದು ಸಾಮಾನ್ಯ array ನಲ್ಲಿ, level ನಂತರ level ಆಗಿ
ಇಡುತ್ತೇವೆ: ಮೊದಲು root, ನಂತರ ಅದರ ಎರಡು children, ನಂತರ ಅವುಗಳ ನಾಲ್ಕು children, ಹೀಗೆ ಮುಂದೆ. ಯಾವುದೇ
pointers ಬೇಕಾಗಿಲ್ಲ. ಸ್ವಲ್ಪ ಲೆಕ್ಕ ಮಾಡಿದರೆ ಯಾವುದೇ value ನ ಕುಟುಂಬ ಸಿಗುತ್ತದೆ:

- Index `i` ನಲ್ಲಿರುವ value ನ **parent** `(i - 1) / 2` ನಲ್ಲಿ ಇರುತ್ತದೆ (ಪೂರ್ಣ ಸಂಖ್ಯೆಯ ಭಾಗಾಕಾರ,
  whole-number division).
- ಅದರ **left child** `2 * i + 1` ನಲ್ಲಿ, **right child** `2 * i + 2` ನಲ್ಲಿ ಇರುತ್ತದೆ.

ಆದ್ದರಿಂದ `[5, 17, 13, 42, 25, 30, 60]` ಎಂಬ array ಈ ಮರ: `5` ಮೇಲೆ, ಅದರ ಕೆಳಗೆ `17` ಮತ್ತು `13`, ನಂತರ
`17` ರ ಕೆಳಗೆ `42` ಮತ್ತು `25`, ಮತ್ತು `13` ರ ಕೆಳಗೆ `30` ಮತ್ತು `60`. ಯಾವುದೇ parent ಮತ್ತು ಅದರ children
ನೋಡಿ: parent ಯಾವಾಗಲೂ ಚಿಕ್ಕದು. ಇದೇ **heap ನ ನಿಯಮ** (heap rule).

ಮರ ಯಾವಾಗಲೂ ಮೇಲಿನಿಂದ ಕೆಳಗೆ, ಎಡದಿಂದ ಬಲಕ್ಕೆ, ಯಾವುದೇ ಖಾಲಿ ಜಾಗ ಬಿಡದೆ ತುಂಬುತ್ತದೆ. ಇಂತಹ ಮರವನ್ನು
**complete** ಎನ್ನುತ್ತಾರೆ. ಇದರಿಂದಲೇ ಅದನ್ನು array ನಲ್ಲಿ ತುಂಬಲು ಸಾಧ್ಯ: ಮುಂದಿನ ಖಾಲಿ index ಯಾವಾಗಲೂ ಮರದ
ಮುಂದಿನ ಖಾಲಿ ಜಾಗವೇ.

ನಾವು `count` ಇಟ್ಟುಕೊಳ್ಳುತ್ತೇವೆ, ಅಂದರೆ heap ನಲ್ಲಿರುವ values ಸಂಖ್ಯೆ, ಮತ್ತು ಒಂದು ನಿಗದಿತ **capacity**.

> **ನಾವೇ ಏಕೆ ಕಟ್ಟಬೇಕು?** ಪ್ರತಿ ಭಾಷೆಯಲ್ಲೂ heap ಅಥವಾ priority queue ಸಿದ್ಧವಾಗಿ ಸಿಗುತ್ತದೆ: Python ನಲ್ಲಿ
> `heapq`, C++ ನಲ್ಲಿ `std::priority_queue`, Java ದಲ್ಲಿ `PriorityQueue`, PHP ಯಲ್ಲಿ `SplMinHeap`.
> JavaScript ನಲ್ಲಿ built-in ಯಾವುದೂ ಇಲ್ಲ, ಆದ್ದರಿಂದ ಜನ ನಿಖರವಾಗಿ ಈ class ಅನ್ನೇ ಬರೆಯುತ್ತಾರೆ. ಒಮ್ಮೆ ನೀವೇ
> ಕಟ್ಟಿದರೆ ಆ tools ಏಕೆ ವೇಗ ಎಂದು ಅರ್ಥವಾಗುತ್ತದೆ, ಮತ್ತು interview ಗಳಲ್ಲಿ ಈ ಪ್ರಶ್ನೆ ತುಂಬಾ ಕೇಳುತ್ತಾರೆ.

## Operations

Heap ಗೆ ಮೂರು ಮುಖ್ಯ operations ಇವೆ. `peek` ತುಂಬಾ ಸರಳ. `insert` ಮತ್ತು `removeMin` ಪ್ರತಿಯೊಂದೂ ಮರದಲ್ಲಿ
ಮೇಲೆ ಅಥವಾ ಕೆಳಗೆ ಒಂದು ಸಣ್ಣ ನಡಿಗೆಯಿಂದ heap ನ ನಿಯಮವನ್ನು ಸರಿಪಡಿಸುತ್ತವೆ.

### insert: ಒಂದು value ಸೇರಿಸುವುದು

1. `count` ಮತ್ತು `capacity` ಸಮವಾಗಿದ್ದರೆ heap ತುಂಬಿದೆ. Error ಕೊಟ್ಟು ನಿಲ್ಲಿಸಿ.
2. ಹೊಸ value ಅನ್ನು ಮೊದಲ ಖಾಲಿ ಜಾಗದಲ್ಲಿ, ಅಂದರೆ index `count` ನಲ್ಲಿ ಇಡಿ, ಮತ್ತು `count` ಗೆ ಒಂದು ಸೇರಿಸಿ.
   ಈಗ ಅದು ಅತ್ಯಂತ ಹೊಸ leaf, ಕೆಳಗೆ ಬಲಭಾಗದಲ್ಲಿ.
3. **Sift up:** value ತನ್ನ parent ಗಿಂತ ಚಿಕ್ಕದಾಗಿರುವವರೆಗೂ ಎರಡನ್ನೂ swap ಮಾಡಿ. ಪ್ರತಿ swap value ಅನ್ನು
   ಒಂದು level ಮೇಲೆ ಏರಿಸುತ್ತದೆ. ಅದರ parent ಚಿಕ್ಕದಾದಾಗ, ಅಥವಾ ಅದು root ತಲುಪಿದಾಗ ನಿಲ್ಲಿಸಿ.

<!-- code: insert -->

`[17, 42, 30]` ನಲ್ಲಿ `8` insert ಮಾಡಿ: ಅದು index `3` ನಲ್ಲಿ, `42` ರ ಕೆಳಗೆ ಬೀಳುತ್ತದೆ. ಅದು `42` ಗಿಂತ
ಚಿಕ್ಕದು, ಆದ್ದರಿಂದ ಅವು swap ಆಗುತ್ತವೆ. ಈಗ ಅದು `17` ರ ಕೆಳಗಿದೆ, ಇನ್ನೂ ಚಿಕ್ಕದೇ, ಆದ್ದರಿಂದ ಮತ್ತೆ swap
ಆಗುತ್ತವೆ. ಫಲಿತಾಂಶ: `[8, 17, 30, 42]`, ಎರಡು swaps. Demo output ನಲ್ಲಿ ಪ್ರತಿ `insert` ಸಾಲೂ ಎಷ್ಟು swaps
ಆದವು ಎಂದು ತೋರಿಸುತ್ತದೆ.

### removeMin: ಅತಿ ಚಿಕ್ಕ value ತೆಗೆಯುವುದು

1. `count` ನ value `0` ಆಗಿದ್ದರೆ heap ಖಾಲಿ ಇದೆ. Error ಕೊಟ್ಟು ನಿಲ್ಲಿಸಿ.
2. Root ಅನ್ನು ನೆನಪಿಟ್ಟುಕೊಳ್ಳಿ: ಅದೇ ಅತಿ ಚಿಕ್ಕ value, ನಾವು return ಮಾಡುವುದು ಅದನ್ನೇ.
3. **ಕೊನೆಯ** value ಅನ್ನು root ನ ಜಾಗಕ್ಕೆ ಸರಿಸಿ, `count` ನಿಂದ ಒಂದು ಕಳೆಯಿರಿ. ಮರ ಈಗಲೂ complete ಆಗಿದೆ,
   ಆದರೆ ಹೊಸ root ಬಹುಶಃ ತುಂಬಾ ದೊಡ್ಡದು.
4. **Sift down:** value ಅನ್ನು ಅದರ ಎರಡು children ಜೊತೆ ಹೋಲಿಸಿ. ಯಾವುದಾದರೂ child ಚಿಕ್ಕದಾಗಿದ್ದರೆ,
   **ಚಿಕ್ಕ** child ಜೊತೆ swap ಮಾಡಿ ಅಲ್ಲಿಂದ ಮುಂದುವರಿಸಿ. ಎರಡೂ children ದೊಡ್ಡದಾದಾಗ, ಅಥವಾ children
   ಉಳಿಯದಿದ್ದಾಗ ನಿಲ್ಲಿಸಿ.

ಚಿಕ್ಕ child ಏಕೆ? ಏಕೆಂದರೆ swap ನಂತರ ಆ child ಇನ್ನೊಂದರ parent ಆಗುತ್ತದೆ, ಮತ್ತು parent ಎರಡೂ children ಗಿಂತ
ಚಿಕ್ಕದಾಗಿರಬೇಕು.

### peek: ಅತಿ ಚಿಕ್ಕ value ನೋಡುವುದು

ಅತಿ ಚಿಕ್ಕ value ಯಾವಾಗಲೂ root, index `0` ನಲ್ಲಿ. `peek` ಅದನ್ನು return ಮಾಡುತ್ತದೆ, ಏನನ್ನೂ
ಬದಲಿಸುವುದಿಲ್ಲ.

## ಇದು ಎಷ್ಟು ವೇಗವಾಗಿದೆ?

`n` values ಇರುವ complete ಮರಕ್ಕೆ ಸುಮಾರು `log₂ n` levels ಮಾತ್ರ ಇರುತ್ತವೆ: `7` values ಗೆ `3` levels
ಬೇಕು, `1,000` values ಗೆ `10`, ಹತ್ತು ಲಕ್ಷಕ್ಕೆ `20`. Sift up ಅಥವಾ sift down ಪ್ರತಿ level ನಲ್ಲಿ ಹೆಚ್ಚೆಂದರೆ
ಒಂದು value ಅನ್ನು ಮಾತ್ರ ನೋಡುತ್ತದೆ, ಆದ್ದರಿಂದ `insert` ಮತ್ತು `removeMin` ಗೆ `O(log n)` ಸಮಯ ಬೇಕು. ಪ್ರತಿ
ಬಾರಿಯೂ ಅತಿ ಚಿಕ್ಕ value ಗಾಗಿ ಸಾಮಾನ್ಯ list ಅನ್ನು ಪೂರ್ತಿ ಹುಡುಕುವುದಕ್ಕೆ (`O(n)`) ಹೋಲಿಸಿದರೆ, heap
ದೊಡ್ಡದಾದ ಮೇಲೆ ಇದು ಭಾರೀ ಉಳಿತಾಯ.

| Operation | ಇದು ಏನು ಮಾಡುತ್ತದೆ | Time |
|---|---|---|
| `insert` | value ಸೇರಿಸಿ ಅದನ್ನು sift up ಮಾಡುವುದು | `O(log n)` |
| `removeMin` | root ತೆಗೆದು, ಕೊನೆಯ value ಅನ್ನು ಮೇಲೆ ಸರಿಸಿ, ಅದನ್ನು sift down ಮಾಡುವುದು | `O(log n)` |
| `peek` | root ನೋಡುವುದು | `O(1)` |
| `isEmpty` | `count` ನ value `0` ಹೌದೇ ಎಂದು ನೋಡುವುದು | `O(1)` |
| ಬೇರೆ ಯಾವುದೇ value ಹುಡುಕುವುದು | ಪ್ರತಿ value ಅನ್ನೂ ನೋಡುವುದು | `O(n)` |

`n` values ಗೆ ಜಾಗ ಇರುವ heap `n` ಜಾಗಗಳ ಒಂದು array ಬಳಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದಕ್ಕೆ `O(n)` memory ಬೇಕು.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **Array sorted ಆಗಿರುತ್ತದೆ ಎಂದು ನಿರೀಕ್ಷಿಸುವುದು.** `17 > 13` ಆಗಿದ್ದರೂ `[5, 17, 13, 42, 25, 30, 60]`
  ಸರಿಯಾದ heap. Parents ಮತ್ತು children ನಡುವೆ ಮಾತ್ರ ಕ್ರಮ ಇದೆ, ಪಕ್ಕದವರ ನಡುವೆ ಅಲ್ಲ. Values sorted ಆಗಿ
  ಬೇಕಿದ್ದರೆ `removeMin` ಬಳಸಿ ಅವುಗಳನ್ನು ಒಂದೊಂದಾಗಿ ತೆಗೆಯಿರಿ.
- **ತಪ್ಪು child ಕಡೆಗೆ sift down ಮಾಡುವುದು.** ಯಾವಾಗಲೂ *ಚಿಕ್ಕ* child ಜೊತೆ swap ಮಾಡಿ. ದೊಡ್ಡದರ ಜೊತೆ swap
  ಮಾಡಿದರೆ ಇನ್ನೊಂದು child ಗೆ heap ನ ನಿಯಮ ಮುರಿಯುತ್ತದೆ.
- **Child ಇಲ್ಲದೆಯೂ ಇರಬಹುದು ಎಂದು ಮರೆಯುವುದು.** ಅವುಗಳನ್ನು ಓದುವ ಮೊದಲು `left < count` ಮತ್ತು
  `right < count` ಪರಿಶೀಲಿಸಿ. Heap ನ ಕೊನೆಯ ಕೆಲವು values ಗೆ ಒಂದೇ child ಇರುತ್ತದೆ ಅಥವಾ ಯಾವುದೂ
  ಇರುವುದಿಲ್ಲ.
- **ಕುಟುಂಬದ ಸೂತ್ರಗಳಲ್ಲಿ ಒಂದರ ವ್ಯತ್ಯಾಸ.** Root index `0` ನಲ್ಲಿದ್ದರೆ, `i` ನ children `2i + 1` ಮತ್ತು
  `2i + 2`. ಕೆಲವು ಪುಸ್ತಕಗಳು index `1` ರಿಂದ ಶುರು ಮಾಡುತ್ತವೆ, ಅಲ್ಲಿ ಅವು `2i` ಮತ್ತು `2i + 1`. ಒಂದನ್ನು
  ಆರಿಸಿ ಅದಕ್ಕೇ ಅಂಟಿಕೊಳ್ಳಿ.
- **ಪರಿಶೀಲಿಸದೆ ತೆಗೆಯುವುದು.** `removeMin` ಅಥವಾ `peek` ಮೊದಲು `isEmpty()` ಪರಿಶೀಲಿಸಿ (ಅಥವಾ error
  ಹಿಡಿಯಿರಿ).

## ಇದು ಎಲ್ಲಿ ಬಳಕೆಯಾಗುತ್ತದೆ?

- ಎಲ್ಲೆಡೆ **priority queues**: printer jobs, ಆಸ್ಪತ್ರೆಯ triage software, ನಿಮ್ಮ operating system ಮುಂದೆ
  ಚಲಾಯಿಸುವ tasks.
- **Heap sort:** ಪ್ರತಿ value ಅನ್ನೂ insert ಮಾಡಿ, ನಂತರ ಖಾಲಿ ಆಗುವವರೆಗೂ `removeMin` ಮಾಡಿ. Values sorted
  ಆಗಿ, `O(n log n)` ಸಮಯದಲ್ಲಿ ಹೊರಬರುತ್ತವೆ. Demo output ನಿಖರವಾಗಿ ಇದರೊಂದಿಗೇ ಮುಗಿಯುತ್ತದೆ.
- **ಅತಿ ಚಿಕ್ಕ ದಾರಿಗಳು (shortest paths).** Map apps ಅತಿ ವೇಗದ ದಾರಿ ಹುಡುಕಲು ಬಳಸುವ Dijkstra's
  algorithm, ಇನ್ನೂ ಭೇಟಿ ನೀಡಬೇಕಾದ ಊರುಗಳನ್ನು ಒಂದು heap ನಲ್ಲಿ ಇಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಅತಿ ಹತ್ತಿರದ ಊರನ್ನು
  ತಕ್ಷಣ ಹಿಡಿಯಬಹುದು.
- **Top-k ಸಮಸ್ಯೆಗಳು**, ಉದಾಹರಣೆಗೆ ಲಕ್ಷಾಂತರ ಹಾಡುಗಳಲ್ಲಿ "ಅತಿ ಹೆಚ್ಚು play ಆದ 10 ಹಾಡುಗಳು", `k` size ನ ಒಂದು
  ಸಣ್ಣ heap ಬಳಸಿ.
- Search engines ಮತ್ತು databases ಮಾಡುವಂತೆ, ಹಲವು sorted lists ಅನ್ನು ಒಂದಾಗಿ **merge** ಮಾಡುವುದು.
- **Timers ಮತ್ತು events:** ಮುಂದೆ ಹೊಡೆಯುವ alarm ಯಾವಾಗಲೂ ಅತಿ ಬೇಗದ ಸಮಯ ಇರುವುದೇ.
