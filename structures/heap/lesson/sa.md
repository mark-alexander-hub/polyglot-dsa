**Heap** इति एकः वृक्षः, यः लघुतमं value सर्वदा उपरि स्थापयति। तस्मिन् प्रत्येकं value तस्य
अधः स्थितयोः द्वयोः value इत्येतयोः अपेक्षया लघुतरम् (अथवा समम्) अस्ति। अतः उपरितनं स्थानम्,
यत् **root** इति उच्यते, सम्पूर्णस्य heap इत्यस्य लघुतमं value अस्ति। एतादृशः heap
**min-heap** इति उच्यते। नियमं विपर्यस्यत, तदा महत्तमं value उपरि तिष्ठति: सः **max-heap**।

**Priority queue** इति रचयितुं heap एव सामान्यः उपायः। priority queue इति एकः queue, यस्मात्
अत्यावश्यकं वस्तु प्रथमं बहिः आगच्छति, वस्तूनि येन केनापि क्रमेण प्रविष्टानि स्युः।

## वास्तविकजीवने

चिकित्सालयस्य आपत्कालीनविभागं चिन्तयत। रोगिणः आगमनक्रमेण न चिकित्स्यन्ते। परिचारिका प्रत्येकं
रोगिणे एकां सङ्ख्यां ददाति, या तस्य आवश्यकतां सूचयति: अतिगम्भीरस्य कृते `1`। वैद्यः सर्वदा
लघुतमसङ्ख्यायुक्तं रोगिणम् अग्रे आह्वयति। नूतनाः रोगिणः नूतनाभिः सङ्ख्याभिः सह आगच्छन्ति एव,
तथा "अग्रे कः?" इति प्रश्नस्य उत्तरं तत्क्षणम् एव देयम्।

heap इति एतदेव करोति:

- नूतनं रोगिणं कतिपयैः एव पदैः **insert** करोति (योजयति)।
- अत्यावश्यकं रोगिणं तत्क्षणम् एव **peek** करोति (पश्यति)।
- अत्यावश्यकं रोगिणं **remove** करोति (अपनयति), ततः अग्रिमः अत्यावश्यकः उपरि आगच्छति।

एषा एव कल्पना **विमानस्थानस्य boarding queue** इत्यत्र (priority groups प्रथमम्), **to-do
list** इत्यत्र (या युष्माकम् अत्यावश्यकं कार्यं सर्वदा उपरि दर्शयति), तथा युष्माकं computer
इत्यस्य अन्तः अपि दृश्यते, यत्र operating system अग्रे चालयितुम् अत्यावश्यकं कार्यं चिनोति।

## एतत् कथं कार्यं करोति

वयं heap इति वृक्षरूपेण चित्रयामः, किन्तु तत् सामान्ये array इत्यस्मिन् एव स्थापयामः, level
इत्यनुसारं क्रमशः: प्रथमं root, ततः तस्य द्वौ children, ततः तयोः चत्वारः children, इत्यादि।
pointer इत्यस्य आवश्यकता नास्ति। अल्पेन गणितेन कस्यापि value इत्यस्य कुटुम्बं लभ्यते:

- index `i` इत्यत्र स्थितस्य value इत्यस्य **parent** `(i - 1) / 2` इत्यत्र अस्ति (पूर्णाङ्कभागः,
  शेषं त्यज्यते)।
- तस्य **left child** `2 * i + 1` इत्यत्र, **right child** `2 * i + 2` इत्यत्र अस्ति।

अतः array `[5, 17, 13, 42, 25, 30, 60]` इति अयं वृक्षः: उपरि `5`, तस्य अधः `17` तथा `13`, ततः
`17` इत्यस्य अधः `42` तथा `25`, `13` इत्यस्य अधः `30` तथा `60`। कमपि parent तस्य children च
पश्यत: parent सर्वदा लघुतरः एव। एषः **heap इत्यस्य नियमः** (heap rule)।

वृक्षः सर्वदा उपरितः अधः, वामतः दक्षिणं च पूर्यते, मध्ये रिक्तस्थानं विना। एतादृशः वृक्षः
**complete** इति उच्यते। अत एव वयं तम् array इत्यस्मिन् स्थापयितुं शक्नुमः: अग्रिमः रिक्तः index
सर्वदा वृक्षस्य अग्रिमं रिक्तं स्थानम् एव।

वयं `count` (heap इत्यस्मिन् values इत्येतेषां सङ्ख्या) तथा निश्चितं **capacity** च रक्षामः।

> च एषः प्रश्नः बहुधा पृच्छ्यते।

## Operations

heap इत्यस्य त्रीणि मुख्यानि operations सन्ति। `peek` अतिसरलम्। `insert` तथा `removeMin`
इत्येते वृक्षे ऊर्ध्वम् अधः वा लघुगमनेन heap इत्यस्य नियमं पुनः साधयतः।

### insert: एकं value योजनम्

1. यदि `count` इति `capacity` इत्यस्य समम्, तर्हि heap पूर्णः। error इति दत्त्वा विरमत।
2. नूतनं value प्रथमे रिक्ते स्थाने, अर्थात् index `count` इत्यत्र, स्थापयत, ततः `count` इत्यस्मिन्
   एकं योजयत। इदानीं तत् नवीनतमः leaf अस्ति, अधः दक्षिणे।
3. **Sift up (ऊर्ध्वम् आरोहणम्):** यावत् तत् value स्वस्य parent इत्यस्मात् लघुतरम्, तावत् द्वयोः
   swap कुरुत। प्रत्येकं swap तत् value एकं level ऊर्ध्वं नयति। यदा तस्य parent लघुतरः, अथवा यदा
   तत् root प्राप्नोति, तदा विरमत।

<!-- code: insert -->

`[17, 42, 30]` इत्यस्मिन् `8` insert कुरुत: तत् index `3` इत्यत्र, `42` इत्यस्य अधः, पतति। तत् `42`
इत्यस्मात् लघुतरम्, अतः तयोः swap भवति। इदानीं तत् `17` इत्यस्य अधः अस्ति, अद्यापि लघुतरम्, अतः
पुनः swap भवति। फलम्: `[8, 17, 30, 42]`, swap द्विवारम्। demo इत्यस्य output इत्यस्मिन् प्रत्येकं
`insert` पङ्क्तिः दर्शयति, कति swaps अभवन् इति।

### removeMin: लघुतमं value अपनयनम्

1. यदि `count` इति `0`, तर्हि heap रिक्तः। error इति दत्त्वा विरमत।
2. root स्मरत: तत् एव लघुतमं value, यत् वयं प्रत्यर्पयामः।
3. **अन्तिमं** value root इत्यस्य स्थानं नयत, ततः `count` एकेन न्यूनं कुरुत। वृक्षः अद्यापि
   complete अस्ति, किन्तु नूतनः root प्रायः अतिमहान्।
4. **Sift down (अधः अवरोहणम्):** तत् value स्वस्य द्वाभ्यां children इत्येताभ्यां सह तुलयत। यदि
   कश्चित् child लघुतरः, तर्हि **लघुतरेण** child इत्यनेन सह swap कुरुत, ततः तस्मात् स्थानात् अग्रे
   गच्छत। यदा उभौ children महत्तरौ, अथवा यदा children एव न सन्ति, तदा विरमत।

लघुतरः child किमर्थम्? यतः swap इत्यस्य अनन्तरं सः child अन्यस्य parent भवति, parent च उभाभ्यां
children इत्येताभ्यां लघुतरः भवितव्यः।

### peek: लघुतमं value दर्शनम्

लघुतमं value सर्वदा root एव, index `0` इत्यत्र। `peek` तत् प्रत्यर्पयति, किमपि न परिवर्तयति।

## एतत् कियत् शीघ्रम्?

`n` values युक्तस्य complete वृक्षस्य केवलं प्रायः `log₂ n` levels भवन्ति: `7` values इत्येतेषां
कृते `3` levels, `1,000` इत्येतेषां कृते `10`, दशलक्षस्य कृते `20`। sift up अथवा sift down
प्रत्येकस्मिन् level इत्यस्मिन् अधिकतमम् एकम् एव value पश्यति, अतः `insert` तथा `removeMin`
इत्येतयोः `O(log n)` समयः लगति। प्रतिवारं सामान्यां list सम्पूर्णं पठित्वा लघुतमस्य अन्वेषणस्य
(`O(n)`) अपेक्षया, heap महति सति, एषः महान् लाभः।

| Operation | एतत् किं करोति | Time |
|---|---|---|
| `insert` | एकं value योजयति, ततः तत् ऊर्ध्वं नयति (sift up) | `O(log n)` |
| `removeMin` | root गृह्णाति, अन्तिमं value उपरि नयति, ततः तत् अधः नयति (sift down) | `O(log n)` |
| `peek` | root पश्यति | `O(1)` |
| `isEmpty` | `count` इति `0` अस्ति वा इति पश्यति | `O(1)` |
| अन्यस्य कस्यापि value इत्यस्य अन्वेषणम् | प्रत्येकं value पश्यति | `O(n)` |

`n` values इत्येतेषां स्थानयुक्तः heap `n` स्थानयुक्तम् एकम् array उपयुङ्क्ते, अतः तस्य `O(n)`
memory आवश्यकम्।

## सामान्याः त्रुटयः

- **array इति sorted अस्ति इति आशा।** `[5, 17, 13, 42, 25, 30, 60]` इति उचितः heap, यद्यपि
  `17 > 13`। केवलं parent तथा children क्रमेण सन्ति, पार्श्वस्थाः न। यदि sorted values वाञ्छथ,
  तर्हि `removeMin` इत्यनेन एकैकं बहिः नयत।
- **अनुचितेन child इत्यनेन सह sift down।** सर्वदा *लघुतरेण* child इत्यनेन सह swap कुरुत। महत्तरेण
  सह swap अन्यस्य child इत्यस्य कृते heap इत्यस्य नियमं भनक्ति।
- **child न स्यात् इति विस्मरणम्।** तौ पठनात् पूर्वं `left < count` तथा `right < count` इति
  परीक्षणं कुरुत। heap इत्यस्य अन्तिमानां कतिपयानां values इत्येतेषाम् एकः child अस्ति, अथवा कोऽपि
  नास्ति।
- **कुटुम्बसूत्रेषु एकेन त्रुटिः।** root इति index `0` इत्यत्र सति, `i` इत्यस्य children `2i + 1`
  तथा `2i + 2` भवतः। कानिचित् पुस्तकानि index `1` इत्यतः आरभन्ते, तत्र ते `2i` तथा `2i + 1`। एकं
  चित्वा तस्मिन् एव स्थिराः भवत।
- **अपरीक्ष्य अपनयनम्।** `removeMin` अथवा `peek` इत्यतः पूर्वं `isEmpty()` परीक्षणं कुरुत (अथवा
  error गृह्णीत)।

## एतत् कुत्र प्रयुज्यते?

- सर्वत्र **priority queues**: printer इत्यस्य कार्याणि, चिकित्सालयस्य triage software, युष्माकम्
  operating system अग्रे यानि कार्याणि चालयति तानि।
- **Heap sort:** प्रत्येकं value insert कुरुत, ततः रिक्तं यावत् `removeMin` कुरुत। values क्रमेण
  (sorted) बहिः आगच्छन्ति, `O(n log n)` समये। demo इत्यस्य output एतेन एव समाप्यते।
- **लघुतमः मार्गः (shortest path)।** Dijkstra इत्यस्य algorithm, यं map apps शीघ्रतमं मार्गम्
  अन्वेष्टुम् उपयुञ्जते, गन्तव्यानि नगराणि heap इत्यस्मिन् स्थापयति, येन निकटतमं नगरं तत्क्षणम् एव
  गृह्णाति।
- **Top-k समस्याः**, यथा लक्षशः गीतेभ्यः "अधिकतमं श्रुतानि 10 गीतानि", `k` इति size युक्तेन लघुना
  heap इत्यनेन।
- बहूनां sorted lists इत्येतासाम् एकस्मिन् **संयोजनम् (merge)**, यथा search engines तथा
  databases कुर्वन्ति।
- **Timers तथा events:** अग्रे वादनीयः alarm सर्वदा सः एव, यस्य समयः सर्वेभ्यः पूर्वम्।
