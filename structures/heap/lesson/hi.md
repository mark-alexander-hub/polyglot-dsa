**Heap** एक ऐसा पेड़ (tree) है जो सबसे छोटी value को हमेशा सबसे ऊपर रखता है। इसमें हर value
अपने नीचे लटकी दो values से छोटी (या बराबर) होती है, इसलिए सबसे ऊपर वाली value, जिसे **root**
कहते हैं, पूरे heap की सबसे छोटी value होती है। इस तरह के heap को **min-heap** कहते हैं। नियम
उलट दीजिए, तो सबसे बड़ी value ऊपर बैठती है: उसे **max-heap** कहते हैं।

**Priority queue** बनाने का सबसे आम तरीका heap ही है: ऐसी queue जिसमें सबसे ज़रूरी चीज़ सबसे
पहले बाहर आती है, चाहे चीज़ें अंदर किसी भी क्रम में गई हों।

## असल ज़िंदगी में

किसी अस्पताल के emergency ward के बारे में सोचिए। मरीज़ों का इलाज उस क्रम में नहीं होता जिस क्रम
में वे अंदर आए। एक nurse हर मरीज़ को एक number देती है जो बताता है कि उसकी हालत कितनी ज़रूरी है,
`1` सबसे गंभीर के लिए, और doctor हमेशा उस मरीज़ को अगला बुलाता है जिसका number सबसे छोटा है। नए
मरीज़ नए numbers के साथ आते रहते हैं, और "अगला कौन?" का जवाब तुरंत मिलना चाहिए।

Heap ठीक यही करता है:

- नया मरीज़ कुछ ही steps में **insert** कीजिए।
- सबसे ज़रूरी मरीज़ को तुरंत **peek** से देखिए।
- सबसे ज़रूरी मरीज़ को **remove** कीजिए, और उसके बाद वाला सबसे ज़रूरी मरीज़ ऊपर आ जाता है।

यही idea आपको **airport की boarding queue** में मिलता है (priority groups पहले), उस **to-do
list** में जो आपका सबसे ज़रूरी काम हमेशा सबसे ऊपर दिखाती है, और आपके computer के अंदर, जहाँ
operating system तय करता है कि अगला सबसे ज़रूरी काम कौन सा चलेगा।

## ये काम कैसे करता है

हम heap को एक पेड़ की तरह बनाते हैं, लेकिन उसे एक साधारण array में रखते हैं, level के हिसाब से:
पहले root, फिर उसके दो children, फिर उनके चार children, और इसी तरह आगे। किसी pointer की ज़रूरत
नहीं। थोड़ा सा हिसाब किसी भी value का परिवार ढूँढ देता है:

- Index `i` वाली value का **parent** `(i - 1) / 2` पर है (पूरे number वाला भाग)।
- उसका **left child** `2 * i + 1` पर है, और **right child** `2 * i + 2` पर।

तो array `[5, 17, 13, 42, 25, 30, 60]` ये पेड़ है: `5` सबसे ऊपर, उसके नीचे `17` और `13`, फिर
`17` के नीचे `42` और `25`, और `13` के नीचे `30` और `60`। किसी भी parent और उसके children को
देखिए: parent हमेशा छोटा वाला है। यही **heap का नियम** है।

पेड़ हमेशा ऊपर से नीचे और बाएँ से दाएँ भरा जाता है, बिना किसी खाली जगह के। ऐसे पेड़ को **complete**
कहते हैं। इसी वजह से हम उसे एक array में समेट पाते हैं: अगला खाली index हमेशा पेड़ की अगली खाली
जगह होता है।

हम `count` रखते हैं, यानी heap में values की गिनती, और एक तय **capacity**।

## Operations

Heap के तीन मुख्य operations हैं। `peek` बहुत आसान है। `insert` और `removeMin` दोनों पेड़ में
थोड़ा सा ऊपर या नीचे चलकर heap का नियम ठीक करते हैं।

### insert: एक value जोड़ना

1. अगर `count` और `capacity` बराबर हैं, तो heap भरा हुआ है। Error देकर रुक जाइए।
2. नई value को पहली खाली जगह में रखिए, यानी index `count` पर, और `count` में एक जोड़ दीजिए। अब
   वो सबसे नया leaf है, सबसे नीचे दाईं ओर।
3. **Sift up:** जब तक value अपने parent से छोटी है, दोनों को swap कीजिए। हर swap value को एक
   level ऊपर चढ़ाता है। तब रुकिए जब उसका parent छोटा हो, या वो root तक पहुँच जाए।

<!-- code: insert -->

`[17, 42, 30]` में `8` insert कीजिए: वो index `3` पर, `42` के नीचे आता है। वो `42` से छोटा है,
इसलिए दोनों swap होते हैं। अब वो `17` के नीचे है, अभी भी छोटा है, इसलिए फिर से swap होते हैं।
नतीजा: `[8, 17, 30, 42]`, दो swaps। Demo output में हर `insert` वाली line बताती है कि उसमें
कितने swaps लगे।

### removeMin: सबसे छोटी value निकालना

1. अगर `count` की value `0` है, तो heap खाली है। Error देकर रुक जाइए।
2. Root को याद रखिए: वही सबसे छोटी value है, जिसे हम लौटाएँगे।
3. **आख़िरी** value को root की जगह पर ले आइए और `count` में से एक घटा दीजिए। पेड़ अभी भी complete
   है, लेकिन नया root शायद बहुत बड़ा है।
4. **Sift down:** value की तुलना उसके दोनों children से कीजिए। अगर कोई child छोटा है, तो
   **छोटे वाले** child से swap कीजिए और वहीं से आगे बढ़िए। तब रुकिए जब दोनों children बड़े हों, या
   नीचे कोई child बचा ही न हो।

छोटे वाले child से ही क्यों? क्योंकि swap के बाद वही child दूसरे child का parent बन जाता है, और
parent को दोनों children से छोटा होना चाहिए।

### peek: सबसे छोटी value देखना

सबसे छोटी value हमेशा root होती है, index `0` पर। `peek` उसे लौटाता है और कुछ नहीं बदलता।

## ये कितना तेज़ है?

`n` values वाले complete पेड़ में सिर्फ़ लगभग `log₂ n` levels होते हैं: `7` values के लिए `3`
levels चाहिए, `1,000` values के लिए `10`, और दस लाख के लिए `20`। ऊपर चढ़ने या नीचे उतरने में हर
level पर ज़्यादा से ज़्यादा एक value देखनी पड़ती है, इसलिए `insert` और `removeMin` को `O(log n)`
समय लगता है। हर बार पूरी list में सबसे छोटी value ढूँढने (`O(n)`) के मुकाबले ये बहुत बड़ी बचत है,
खासकर जब heap बड़ा हो जाए।

| Operation | ये क्या करता है | Time |
|---|---|---|
| `insert` | value जोड़कर उसे ऊपर चढ़ाना | `O(log n)` |
| `removeMin` | root निकालना, आख़िरी value ऊपर लाना, उसे नीचे उतारना | `O(log n)` |
| `peek` | root देखना | `O(1)` |
| `isEmpty` | देखना कि `count` की value `0` है या नहीं | `O(1)` |
| कोई और value ढूँढना | हर value को देखना | `O(n)` |

`n` values की जगह वाला heap `n` boxes का एक array इस्तेमाल करता है, इसलिए उसे `O(n)` memory चाहिए।

## आम गलतियाँ

- **ये उम्मीद करना कि array sorted होगा।** `[5, 17, 13, 42, 25, 30, 60]` एक सही heap है, भले ही
  `17 > 13` हो। सिर्फ़ parent और children क्रम में होते हैं, पड़ोसी नहीं। अगर आपको values क्रम में
  चाहिए, तो उन्हें `removeMin` से एक-एक करके निकालिए।
- **गलत child की ओर नीचे उतरना।** हमेशा *छोटे* child से swap कीजिए। बड़े वाले से swap करने पर
  दूसरे child के लिए heap का नियम टूट जाता है।
- **ये भूल जाना कि child हो भी सकता है और नहीं भी।** उन्हें पढ़ने से पहले `left < count` और
  `right < count` जाँचिए। Heap की आख़िरी कुछ values का एक child होता है या कोई नहीं।
- **परिवार वाले formulas में एक का फ़र्क।** Root index `0` पर हो, तो `i` के children `2i + 1` और
  `2i + 2` पर हैं। कुछ किताबें index `1` से शुरू करती हैं, जहाँ वे `2i` और `2i + 1` पर होते हैं।
  एक तरीका चुनिए और उसी पर टिके रहिए।
- **बिना जाँचे निकालना।** `removeMin` या `peek` से पहले `isEmpty()` जाँचिए (या error पकड़िए)।

## ये कहाँ काम आता है?

- **Priority queues** हर जगह: printer के jobs, अस्पताल का triage software, वो tasks जो आपका
  operating system अगली बार चलाता है।
- **Heap sort:** हर value insert कीजिए, फिर खाली होने तक `removeMin` कीजिए। Values sorted होकर
  बाहर आती हैं, `O(n log n)` समय में। Demo output का अंत ठीक इसी से होता है।
- **सबसे छोटा रास्ता।** Dijkstra का algorithm, जिससे map apps सबसे तेज़ रास्ता ढूँढते हैं, बचे हुए
  शहरों को एक heap में रखता है ताकि सबसे पास वाला शहर तुरंत मिल जाए।
- **Top-k वाले सवाल**, जैसे लाखों गानों में से "सबसे ज़्यादा सुने गए 10 गाने", `k` size के एक छोटे
  heap से।
- कई sorted lists को एक में **merge करना**, जैसा search engines और databases करते हैं।
- **Timers और events:** अगला बजने वाला alarm हमेशा वही है जिसका समय सबसे पहले है।
