**Stack** इति एका list अस्ति, यस्यां यूयं वस्तूनि एकस्मिन् एव अन्ते योजयितुं वा अपनेतुं वा शक्नुथ।
सः अन्तः **top** इति कथ्यते। यत् वस्तु यूयम् अन्ते स्थापितवन्तः, तत् एव प्रथमं बहिः आगच्छति। एतत्
**LIFO** इति कथ्यते: *Last In, First Out*, अर्थात् यत् अन्ते आगतं तत् प्रथमं गच्छति।

## वास्तविकजीवने

विवाहभोजस्य buffet इत्यत्र स्थापिताः स्थालिकाः चिन्तयत। स्वच्छाः स्थालिकाः राशेः उपरि स्थाप्यन्ते,
प्रत्येकः अतिथिः च उपरितः एव स्थालिकाम् उद्धरति। कोऽपि मध्यात् अधः वा स्थालिकां न आकर्षति। या
स्थालिका सर्वेभ्यः अन्ते स्थापिता, सा एव प्रथमम् उद्ध्रियते।

यूयम् अजानन्तः एव प्रतिदिनं stack इत्यस्य प्रयोगं कुरुथ:

- Text editor इत्यस्मिन् **Undo** प्रथमं युष्माकं नवीनतमं परिवर्तनम् अपनयति।
- Browser इत्यस्य **back button** युष्मान् तत् page प्रति नयति यत् यूयम् अन्ते उद्घाटितवन्तः।
- उत्पीठिकायां स्थितः **पुस्तिकानां राशिः**: यूयं तां पुस्तिकाम् उद्धरथ यां यूयम् अन्ते स्थापितवन्तः।

## एतत् कथं कार्यं करोति

वयं stack इत्येतत् एकस्य array इत्यस्य उपरि रचयिष्यामः, यस्मिन् boxes इत्येतेषां संख्या निश्चिता
अस्ति। एषा संख्या **capacity** इति कथ्यते। वयम् एकां संख्यां रक्षामः, `top` इति, या top इत्यत्र
स्थितस्य value इत्यस्य index अस्ति।

- यदा stack रिक्तः अस्ति, तदा `top` `-1` भवति, यतः अद्यापि किमपि top value नास्ति।
- यदा stack पूर्णः अस्ति, तदा `top` `capacity - 1` भवति, अर्थात् अन्तिमः box।

<!-- code: setup -->

> **एतत् स्वयं किमर्थं रचयामः?** प्रत्येकस्यां भाषायां पूर्वनिर्मितः stack लभ्यते: Python इत्यस्मिन्
> `list`, C++ इत्यस्मिन् `std::stack`, Java इत्यस्मिन् `ArrayDeque`, JavaScript इत्यस्मिन् array, PHP
> इत्यस्मिन् `SplStack`। एकवारं स्वयं रचयित्वा यूयं जानीथ यत् एते tools युष्मदर्थं किं कुर्वन्ति,
> interview इत्यस्मिन् च एषः प्रश्नः बहुधा पृच्छ्यते।

## Operations

Stack इत्यस्य त्रीणि मुख्यानि operations सन्ति। त्रीणि अपि केवलं top इत्येतत् एव पश्यन्ति।

### push: top इत्यत्र एकस्य value इत्यस्य स्थापनम्

1. यदि `top` पूर्वमेव अन्तिमे box इत्यत्र अस्ति, तर्हि stack पूर्णः अस्ति। तस्मिन् अधिकं योजनम्
   **overflow** इति कथ्यते, अतः वयम् error इति दत्त्वा विरमामः।
2. अन्यथा, `top` इत्येतत् एकं स्थानम् उपरि सारयत।
3. Value इत्येतत् `top` इत्यत्र स्थिते box इत्यस्मिन् स्थापयत।

<!-- code: push -->

### pop: top इत्यत्र स्थितस्य value इत्यस्य अपनयनम्

1. यदि `top` `-1` अस्ति, तर्हि stack रिक्तः अस्ति। रिक्तात् stack इत्यस्मात् अपनयनम् **underflow**
   इति कथ्यते, अतः वयम् error इति दत्त्वा विरमामः।
2. `top` इत्यत्र स्थितं value स्मरत।
3. `top` इत्येतत् एकं स्थानम् अधः सारयत, स्मृतं value च प्रत्यर्पयत (return)।

<!-- code: pop -->

ध्यानं ददत, वयं पुरातनं value **न मार्जयामः**। `top` इत्येतत् अधः सारणं पर्याप्तम्: सः box इदानीं
stack इत्यस्मात् बहिः अस्ति, अग्रिमः `push` च तस्य उपरि नवीनं value लिखिष्यति। उपरि स्थिते
playground इत्यस्मिन् एतानि पुरातनानि values मन्दवर्णेन दृश्यन्ते।

### peek: top इत्येतत् अनपनीय दर्शनम्

`peek` केवलं `top` इत्यत्र स्थितं value प्रत्यर्पयति, किमपि च न परिवर्तयति। यदा यूयं किमपि
निश्चेतुं पूर्वं top इत्यत्र किम् अस्ति इति द्रष्टुम् इच्छथ, तदा एतत् उपयोगि भवति।

## एतत् कियत् शीघ्रम्?

प्रत्येकम् operation केवलं top इत्यत्र स्थितं box एव स्पृशति, stack इत्यस्मिन् कियन्ति अपि values
सन्तु। अतः सर्वाणि समानम् अल्पं च समयं गृह्णन्ति, यत् `O(1)` (constant time) इति लिख्यते।

| Operation | एतत् किं करोति | Time |
|---|---|---|
| `push` | top इत्यत्र value इत्यस्य स्थापनम् | `O(1)` |
| `pop` | top इत्यत्र स्थितस्य value इत्यस्य अपनयनम् | `O(1)` |
| `peek` | top इत्यत्र स्थितस्य value इत्यस्य दर्शनम् | `O(1)` |
| `isEmpty` | `top` `-1` अस्ति न वा इति परीक्षणम् | `O(1)` |
| कस्यचित् value इत्यस्य अन्वेषणम् | प्राप्तिपर्यन्तम् एकैकशः values इत्येतेषां pop करणम् | `O(n)` |

`n` values इत्येतेषां स्थानयुक्तः stack `n` boxes उपयुङ्क्ते, अतः तस्य `O(n)` memory आवश्यकम्।

## सामान्याः त्रुटयः

- **अपरीक्ष्य pop करणम्।** `pop` अथवा `peek` इत्यतः पूर्वं `isEmpty()` इत्यस्य परीक्षणं कुरुत (अथवा
  error गृह्णीत)। Underflow इति stack इत्यस्य सर्वाधिकं सामान्यः bug अस्ति।
- **अन्तयोः विपर्ययः।** Top सः अन्तः यत्र अन्तिमं value गतम्। यदि युष्माकं `pop` *प्रथमं* push कृतं
  value प्रत्यर्पयति, तर्हि यूयं प्रमादेन queue रचितवन्तः।
- **"पूर्णः" इत्यत्र एकेन त्रुटिः।** अन्तिमस्य box इत्यस्य index `capacity - 1` अस्ति, न तु `capacity`।
- **क्रमः विपरीतः भवति इति विस्मरणम्।** `1, 2, 3` push कृत्वा त्रिवारं pop कुरुत: यूयं `3, 2, 1`
  प्राप्स्यथ। Stack क्रमं विपरीतं करोति।

## एतत् कुत्र प्रयुज्यते?

- **Function calls।** यदा एकं function अन्यत् function आह्वयति, तदा computer अपूर्णं कार्यं *call
  stack* इत्यत्र push करोति, आन्तरिकं function समाप्ते च तत् pop करोति। यत् function स्वयमेव सदा
  आह्वयति, तस्य स्थानं समाप्तं भवति: एषः एव वास्तविकः **stack overflow**।
- **Undo, back buttons च**, यथा उपरि दृष्टम्।
- Code इत्यस्मिन् **brackets इत्येतेषां परीक्षणम्**: प्रत्येकं `(` push क्रियते, प्रत्येकं `)` च
  स्वयुग्मं pop करोति।
- कस्यचित् शब्दस्य list इत्यस्य वा **क्रमस्य विपर्ययः**।
- Graphs, mazes इत्येतेषु **depth-first search**, यत् यूयम् अग्रे पठिष्यथ।

## एतानि कृत्वा पश्यत

1. `4, 8, 15` push कुरुत, ततः एकवारं pop कुरुत। इदानीं top इत्यत्र किम् अस्ति? स्वम् उत्तरं
   playground इत्यस्मिन् पश्यत।
2. Stack इत्यस्य साहाय्येन `STACK` इति शब्दस्य क्रमं विपरीतं कुरुत: प्रत्येकम् अक्षरं push कुरुत,
   ततः सर्वाणि pop कुरुत।
3. एकं function लिखत यत् परीक्षते `"(()())"` इत्यस्मिन् brackets balanced सन्ति न वा। ततः `"(()"`
   इत्यनेन पुनः कुरुत।
4. Program इत्येतत् तथा परिवर्तयत यथा पूर्णे stack इत्यस्मिन् `push` करणे error इत्यस्य स्थाने
   capacity द्विगुणा भवेत्। Python lists, C++ vectors च एवमेव वर्धन्ते।
